# 运维与 E2E 细则

> 来源: strict.md 的运维规则 / E2E 验收 / 网络环境段

---

## 运维规则

```
0. 指令禁止: 2>&1
1. 测试: uv run pytest
2. 变更前: 先停止可能锁定的进程（Windows 进程/Docker/WSL）
3. Docker: 本地验证时确保 Docker 已停止
4. 数据库: 只用业务代码操作，不直接操作 DB
5. 修复中遇脏逻辑 → 记录提醒，方便后续治理
6. 优先使用已有轮子
```

---

## E2E 验收原则

```
- e2e 过程中即时用 vision-audit 看界面，不积压问题
- 已知存在问题时，跑全量 e2e 无意义，即时诊断优先
- e2e 全量太重，只提醒用户主动触发，不自发跑
```
