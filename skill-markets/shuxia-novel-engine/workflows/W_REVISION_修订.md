# W_REVISION · 修订工作流

> 场景: 全稿初稿完成后的第二轮、第三轮修改
> 不同于 P3（写→评→修单场景循环），修订是全局视角的结构性调整

---

## 与 P3 的区别

| | P3 细节降噪 | W_REVISION 修订 |
|---|---|---|
| 粒度 | 单场景 | 全卷/全局 |
| 目标 | 场景质量达标 | 结构/节奏/弧线优化 |
| 工具 | evaluate.py(单章) | evaluate.py(全卷统计) + ripple.py(全局) |
| 频率 | 写每个场景时 | 每轮改稿时 |

---

## 修订流程

### R1: 结构修订

```
1. 全卷六维统计:
   for ch in 1..N: evaluate.py --chapter ch --type auto
   → 生成全卷六维曲线

2. 识别结构问题:
   - 塌陷区: 连续>=3章总分<70
   - 过度区: 连续>=4章总分>85
   - 失衡: 某维度全卷平均分<60
   - 断裂: 相邻章总分之差>30

3. 结构修复:
   - 塌陷区 → 重新设计该段的核心事件
   - 过度区 → 插入过渡章或放缓
   - 失衡 → 补强弱势维度
   - 断裂 → 插入缓冲章
```

### R2: 角色弧修订

```
1. 提取每个主要角色的出场章
2. 检查弧线完整性:
   - 状态转变是否有触发事件
   - 每次Δ≤1级
   - 方向一致(不来回跳)
3. 修复断裂弧线
```

### R3: 伏笔修订

```
1. run: check.py → 伏笔回收率
2. <90%: 列出未回收伏笔
3. 决策: 补回收章 OR 标记为"故意不回收"OR 删除
4. 更新伏笔追踪双表
```

### R4: 涟漪终审

```
1. ripple.py --full-project
2. 修复所有CRITICAL
3. HIGH<=3且有修复计划
```

---

## 修订轮次建议

```
第一稿 → R1结构修订 → R2角色弧修订
第二稿 → R1结构复查 → R3伏笔修订
第三稿 → R4涟漪终审 → 提交P4润色
```
