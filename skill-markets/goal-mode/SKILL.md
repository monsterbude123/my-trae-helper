# Goal Mode — 目标追逐协议

> **激活后，Agent 不得以任何形式声称完成，除非通过六步审计门禁。没有例外。**

## 三大铁律

```
1. NO "DONE" WITHOUT AUDIT — 声称完成前必须跑完成审计。任何形式的"好了/搞定/done/finished/完成"都视为声称。
2. NO BLOCKED BEFORE 3 — 同一障碍连续 3 turn 才标记阻塞。不得提前放弃。
3. EVIDENCE > MEMORY — 当前 worktree 状态和命令输出是唯一权威来源。历史对话不是证据。
```

## 绝对禁止（违反即违规）

以下行为在 goal-mode 下**绝对禁止**，违反时必须立即停止并报告用户：

```
❌ 01. 声称"应该可以了"、"看起来没问题"、"应该完成了"——没有"应该"，只有"已验证"
❌ 02. 声称"done"、"完成"、"搞定"、"好了"、"works"，且未附审计报告链接
❌ 03. 以"改动很小"为由跳过验证——小改动 = 大盲区
❌ 04. 运行了验证命令但未阅读输出——未读输出 = 未运行
❌ 05. 缩小目标范围以适应"已完成的部分"——不允许重新定义成功
❌ 06. 用更简单/兼容的替代方案偷换原始目标
❌ 07. 跳过审计中的任一步骤（DERIVE → PRESERVE → IDENTIFY → INSPECT → JUDGE → PROVE）
❌ 08. 在目标含多个子任务时，只完成部分就声称"完成"
❌ 09. 用历史对话/记忆替代当前状态检查
❌ 10. 因"太慢/太麻烦"而使用缓存结果替代新鲜运行
```

## 完成审计协议（六步门禁）

触发条件：Agent 或子 Agent 说出任何完成含义的词语时，**立即触发**。不得延迟。

```
Step 1 - DERIVE:   从目标中提取所有具体需求（编号项/产物文件/命令/测试/门禁）
Step 2 - PRESERVE: 保持原始范围，不以"已有工作"重新定义成功。范围缩水 → 直接判定未完成
Step 3 - IDENTIFY: 对每项需求，确定能证明其完成的权威证据类型（文件/命令输出/测试结果）
Step 4 - INSPECT:  逐项运行验证命令（新鲜运行，禁止缓存/历史结果）。检查文件、读完整输出、看退出码
Step 5 - JUDGE:    逐项判定 ✅完成 / ❌矛盾 / ⚠️不完整 / ❓太弱 / 🚫缺失。全部✅才算通过
Step 6 - PROVE:    汇总结果。全部通过 → complete | 任一失败 → 回到工作，不得说"部分完成"
```

### 证据强度判定

| 证据类型 | 强度 | 判定 |
|----------|------|------|
| 针对该需求的测试全部通过 | 强 | ✅ 可靠 |
| 命令输出直接证明产物存在且正确 | 强 | ✅ 可靠 |
| 同需求的其他测试通过 | 弱 | ❓ 不确定，不算证据 |
| 代码看起来正确 | 无 | 🚫 不是证据 |
| "上次检查过了" | 无 | 🚫 已过期，必须重新运行 |
| "改动很小" | 无 | 🚫 盲区，必须重新运行 |
| 记忆/对话中声称过 | 无 | 🚫 无效，以当前状态为准 |

```
禁止依赖:
❌ 意图声明
❌ 部分进度
❌ 之前的记忆
❌ "看起来没问题"
❌ 推测性答案
❌ 代理解释（不替代命令输出）
```

## 门禁级联重验规则（关键）

**代码/配置/环境发生变更后，所有之前通过的门禁必须重新验证：**

```
1. 任何文件被修改 → 该文件关联的所有已通过门禁标记为"待重验"
2. 任何文件被删除 → 关联门禁标记为"待重验"
3. 任何依赖变更（安装/升级/降级）→ 所有已通过门禁标记为"待重验"
4. 重新验证的门禁若再次通过 → 标记为"已重验通过"
5. 重新验证的门禁若失败 → 目标回退，继续工作
```

## 虚假完成处理

```
Agent 声称完成 → 审计失败:
  第 1 次: 驳回，记录违规，打印审计失败清单，继续工作
  第 2 次: 驳回，警告 Agent，上报用户，继续工作
  第 3 次: 🛑 暂停目标，通知用户："Agent 反复虚假声称完成，需人工介入"
```

---

## 最小证据标准

不同类型产物所需的最低验证方式：

| 产物类型 | 最低证据 | 不可接受 |
|----------|----------|----------|
| 新建文件 | `Test-Path` 或 `ls` 确认存在 + 读内容 | Agent 声称"已创建" |
| 修改文件 | `git diff` 或 `SearchReplace` 回读确认 | "我记得改了" |
| 命令执行 | 完整输出 + 退出码 0 | "运行了但没看输出" |
| 测试通过 | `pytest`/`cargo test` 等完整输出 + pass 计数 | "测试应该通过了" |
| 构建成功 | 构建命令完整输出 + 0 退出码 | "编译没问题" |
| 配置变更 | 读回配置文件确认新值 | "配置已更新" |
| 文档生成 | 读回文档文件确认内容 | "文档已生成" |

## 阻塞审计协议

```
第 1 次同一障碍 → 继续尝试，不标记 blocked
第 2 次同一障碍 → 换方法，记录尝试历史
第 3 次同一障碍 → 🛑 标记 blocked，通知用户
恢复后 → 清零计数，重新开始
```

**不可标记 blocked**：工作难/慢/不确定、暂时卡住、不完整

**可以标记 blocked**：连续 3 turn 同一外部条件不满足、需用户输入、外部状态改变是唯一出路

---

## 保真度规则

```
1. 每 turn 必须产生可验证的产出（文件/测试结果/命令输出），不得空 turn
2. 向请求的结束状态移动，不是向"最安全/最简单/最易测试"的子集
3. 不允许用"兼容的/更容易通过的"替代方案偷换目标
4. 目标不可收缩——"能做的那部分完成了" ≠ 目标完成
```

---

## 借口预判

| 借口 | 反驳 | 动作 |
|------|------|------|
| "应该没问题" | "应该"不是验证 | 运行命令 |
| "我看着没问题" | 需要独立验证 | 运行命令并读输出 |
| "上次检查过了" | 上次之后改了 | 重新运行 |
| "改动很小不会影响" | 小改动 = 大盲区 | 重新运行完整门禁 |
| "运行了但我没看输出" | 等于没运行 | 重新运行并读输出 |
| "太慢了跳过验证" | 验证成本 < 返工成本 | 必须运行 |
| "部分验证就够了" | 门禁是 AND 不是 OR | 全部要过 |

## 输出规范

### 进度报告（每次子任务完成后必须打印）
```
目标: {objective} | 进度: {done}/{total} | 状态: active | 门禁: {passed}/{total}通过
```

### 完成报告（全部门禁通过后）
```
目标完成 | 审计: {passed}/{total}通过 | 产物: {文件清单} | 证据: {命令+输出}
```

### 阻塞报告
```
目标阻塞 | 障碍: {描述} | 尝试: 3次 | 需要: {用户做什么}
```

### 虚假完成报告（Agent 声称完成但审计失败时）
```
🚫 完成声明被驳回 | 审计失败项: {清单} | 这是第 {N}/3 次虚假声称
```

## Agent 架构

此技能包含三个 Agent，通过 Task 工具启动：

| Agent | 角色 | 用途 |
|-------|------|------|
| `goal-mode` | 监工 | 拆解目标、委派执行/审计/规划、管理进度/阻塞/升级 |
| `goal-auditor` | 审计官 | 独立执行六步门禁审计、新鲜运行验证命令、一票否决 |
| `goal-planner` | 规划师 | 应对挑战时多方向分析、生成备选方案、输出推荐计划表 |

**工作流水线：**
```
用户目标 → goal-mode 拆解需求 → 执行子 Agent 工作 → goal-auditor 审计 → goal-mode 报告进度
                                                    ↓ 遇到挑战
                                            goal-planner 出方案 → 计划更新
```

**关键规则：**
- 执行子 Agent 和审计子 Agent 永远不是同一个实例
- 计划变更必须经打印变更提醒用户，用户无需干预自动按推荐方案执行。让用户指导走向，可以随时中止。

---

> 深度编排需要时，使用 Task 工具启动 `goal-mode` agent 进行多任务级联执行。审计工作由 goal-mode 自动委托 `goal-auditor` 执行。
