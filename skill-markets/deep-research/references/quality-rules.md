# Deep Research — 质量规则 + 反例库

> SKILL.md §3 铁律的逐条展开 + 反例。

---

## 铁律 1: 每条主张必有来源

```
MUST:
  - 每个数字 / 事实 / 引用 → inline 标 [Source](url)
  - 无源陈述必须删除或改写为"基于推理"
  - 来源类型: 学术 > 官方 > 知名媒体 > 行业报告 > 博客 > 论坛

反例:
  ❌ "全球 AI 医疗市场到 2030 年将达 1000 亿美元"
  ✅ "全球 AI 医疗市场预计 2030 年达 1000 亿美元（CAGR 37%），来源 Grand View Research 2024 报告（[GVR](https://...)）"
```

---

## 铁律 2: 交叉验证

```
MUST:
  - 关键事实 ≥ 2 个独立来源印证
  - 仅 1 来源 → 标 ⚠ unverified
  - 多源冲突 → 列差异 + 给调和判断

独立来源定义:
  - 不同机构（如 WHO + CDC，不是一篇引用另一篇）
  - 不同方法（数据 vs 调研 vs 案例）
  - 不同时点（不是同日同稿的两个媒体转载）

反例:
  ❌ 同一新闻通稿被 5 家媒体转载，标 5 个来源
  ✅ 1 个通稿 + 1 个独立分析 + 1 个数据点
```

---

## 铁律 3: 时效性优先

```
默认窗口:
  - 技术 / AI / 政策类: 12 个月内
  - 学术 / 基础科学: 24 个月内
  - 历史 / 框架类: 不限
  - 用户明示老资料可接受 → 例外

表达:
  - 默认不说日期（读者假定新）
  - 关键时效性 → 标日期（如"截至 2024 Q3"）
  - 矛盾新旧数据 → 标两个日期 + 解释

反例:
  ❌ "目前 PyTorch 是主流"（无日期，"目前"是何时？）
  ✅ "2025 年 6 月，PyTorch 在 Papers With Code 占比 65%（[来源](url)）"
```

---

## 铁律 4: 承认空白

```
MUST:
  - 找不到好信息 → 直说"未找到充分数据"
  - 找得到但质量低 → 明示 + 给链接
  - 不要为了"完整性"编造

反例:
  ❌ 子问题 5 找不到资料 → 编一段"基于行业经验..."
  ✅ 子问题 5 找不到资料 → "未找到 ≥ 2 个独立来源；仅 X 媒体提及，建议进一步访谈验证"
```

---

## 铁律 5: 区分事实/推断

```
MUST:
  - 已发生事实 → 直陈 + 来源
  - 估算 / 预测 → 标"估算" / "预测" + 来源 + 方法
  - 个人观点 / 立场 → 标"X 认为..." 不用"X 觉得"是事实

反例:
  ❌ "到 2030 年 AI 将取代 30% 客服工作"
  ✅ "Gartner 2024 预测到 2030 年 AI 可能影响 30% 客服岗位（[Gartner](url)）；该数字为估算，基于任务自动化率推算，未含行业差异"
```

---

## 铁律 6: No hallucination

```
MUST:
  - 不知道 → "未找到足够数据"
  - 不确定 → "基于 X 推理，待验证"
  - LLM 训练知识可能过时 → 当前研究只信工具返回的内容

反例:
  ❌ 直接写 "Sora 2 在 2025 年 12 月发布，支持 60 秒视频"
     （可能训练数据里有，工具查不到 → 幻觉风险）
  ✅ "Sora 当前公开版本功能（按 [OpenAI 官网](url) YYYY-MM-DD 抓取）"
```

## 综合反例：常见失败模式

### 失败 1: 搜索摘要当事实

```
现象: 看完 firecrawl_search 返回的 5 个 snippet 就开始写
后果: snippet 经常断章 + 来源质量未验 + 关键限定条件丢失
修正: 必走 Step 4 抓全文 + 至少 1 个深度阅读
```

### 失败 2: 单源依赖

```
现象: 找到 1 篇好文章后 90% 内容来自它
后果: 该来源的偏见/错误被放大
修正: 必走铁律 §2 交叉验证
```

### 失败 3: 时间漂移

```
现象: 用 2022 的数据讲 2026 的现状
后果: 时效失效
修正: 铁律 §3 + 报告里标日期
```

### 失败 4: 报告堆砌无结论

```
现象: Executive Summary = "本文研究了 X 的 Y 方面"（废话）
后果: 用户读完不知道结论
修正: Summary 必须给"该领域的关键判断是什么"（3-5 句）
```

### 失败 5: 长报告全塞聊天

```
现象: 8000 字报告直接输出
后果: 上下文爆 + 用户没法引用
修正: Step 6 落盘 + 摘要 + 关键 takeaways
```

## 质量自检清单（交付前必走）

```
[ ] 每条事实/数字有 inline 引用
[ ] 关键事实 ≥ 2 独立来源
[ ] 单源声明已标 ⚠ unverified
[ ] 时效性符合窗口（< 12 / 24 月）
[ ] 数据空白已主动声明
[ ] 估算/预测/观点已分别标注
[ ] Executive Summary 是结论（不是"本文研究..."）
[ ] Sources 章节有完整 URL
[ ] Methodology 字段齐全（工具 + 查询 + 时间）
[ ] 长报告已落盘 + 聊天发摘要
```
