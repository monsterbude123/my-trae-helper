## §1 关卡流程图

与剧情树的区别：剧情树管"玩家看到什么故事"，关卡流程图管"玩家玩什么机制"。

### 结构选择

| 结构 | 特征 | 适用 |
|------|------|------|
| 线型 (Linear) | A→B→C，无分支 | 教程关 / 叙事驱动强 |
| 分支 (Branching) | A→B1 or B2→C | 玩家选择风格/难度 |
| 轮辐 (Hub & Spoke) | 中央枢纽 → 多个可攻略关卡 | 开放世界 / 选关制 |
| 网状 (Web) | 多条路径可达同一目标 | 银河城 / 沉浸式模拟 |
| 非线型 (Non-linear) | 顺序任意，渐进解锁 | 开放世界 / Roguelike |

输出格式：

```
[第1关: 教程] ─→ [第2关: 森林] ─┬→ [第3关: 地牢A]
                                └→ [第4关: 山脉B] ─→ [第5关: Boss]
```

## §2 难度曲线

### 4 段节奏模板

| 段 | 位置 | 目的 | 难度 |
|----|------|------|------|
| 引入 (Introduce) | 前 10%~15% | 新机制安全试错 | 低 |
| 掌握 (Master) | 15%~70% | 机制组合/挑战升级 | 逐步递增 |
| 挑战 (Challenge) | 70%~90% | 机制极限测试/Boss 战 | 峰顶 |
| 休息 (Rest) | 90%~100% | 成就感/叙事收束 | 回落 |

难度可视化：

```
难度
 ^         ● ← Boss 战（峰顶）
│        / \
│       /   \
│      /     \___ ● ← 终局（成就感）
│     /           
│    /  ← 逐步递增
│   /
│  ● ← 引入（低起点）
└──────────────────→ 进度
```

## §3 参数矩阵

逐关卡定义参数。所有数值为"基准值乘数"（第 1 关 = 1.0）。

| 关卡 | 结构 | 敌人HP乘数 | 敌人ATK乘数 | 资源获取 | 时间限制 | 新机制引入 |
|------|------|-----------|------------|----------|----------|-----------|
| 1 | 线型 | 1.0 | 1.0 | 1.0 | 无 | 基础移动/攻击 |
| 2 | 线型 | 1.2 | 1.1 | 0.9 | 无 | 跳跃/攀爬 |
| 3 | 分支A | 1.5 | 1.3 | 0.8 | 180s | 元素克制(火) |
| 3B| 分支B | 1.4 | 1.5 | 1.0 | 无 | 元素克制(冰) |
| 4 | Hub | 2.0 | 1.8 | 0.6 | 无 | Boss 机制 |

参数列按需扩展：敌人数量、陷阱密度、回复点间距、隐藏区域数。

## §4 教学关卡设计

### 4.1 无文本教学原则

能用关卡设计教的，不用文字教：

| 传统方式 | 无文本方式 |
|----------|-----------|
| 弹窗"按 A 跳跃" | 面前一个只能跳过去的坑 |
| 教程文字"火克草" | 草属性敌人旁边放火把 |
| 提示"按B格挡" | 必死攻击前放一个只有格挡能破的障碍 |

### 4.2 安全第一机制

新机制首次出现时，失败代价为 0 或极低（立即重生/无惩罚）。

### 4.3 机制递增引入

每次只引入 1 个新机制。第 N 关 = N-1 关机制 + 1 个新机制。
禁止"第 3 关同时教跳跃 + 冲刺 + 滑铲"。

## §5 关卡-剧情联动

| 剧情事件 | 关卡机制变化 | 示例 |
|----------|-------------|------|
| 角色入队 | 解锁该角色能力对应的关卡解法 | 二段跳角色入队 → 出现高处平台 |
| 关键道具获取 | 解锁此前不可达区域 | 获得钥匙 → 之前锁住的门现在可开 |
| 剧情转折 | 改变关卡规则 | 背叛发生后 → 队友变为敌人 |
| 结局分支 | 关卡最终形态不同 | 真结局入口 vs 普通结局入口 |

联动铁律：
1. 剧情节点触发关卡机制变化 → 关卡设计师和剧情策划必须对齐 flag 变量名
2. 关卡完成解锁剧情分支 → 关卡通关 = 设置某个 flag
3. 同一变量名不得同时在剧情和关卡中使用含义冲突的值
