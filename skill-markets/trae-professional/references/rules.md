# 规则系统 (Rules)

## 应用场景

| 目标 | 说明 |
|------|------|
| 提升效率 | 个人经验转化为可复用规则，减少沟通成本 |
| 统一标准 | 团队规范结构化为规则，保持一致性 |
| 保障质量 | 明确架构设计、命名规范等核心约束 |

## 规则类型

| 类型 | 描述 | 示例 |
|------|------|------|
| 全局规则 | 所有项目生效 | 语言风格、操作系统偏好 |
| 项目规则 | 仅当前项目生效 | 代码风格、框架限定、API 约束 |

## 四种生效方式

| 生效方式 | alwaysApply | 额外配置 |
|----------|-------------|----------|
| 始终生效 | true | 无 |
| 指定文件生效 | false | `globs` 字段，如 `*.js, src/**/*.ts` |
| 智能生效 | false | `description` 描述适用场景 |
| 手动触发生效 | false | 对话中用 `#Rule` 引用 |

## 多层规则嵌套

`.trae/rules/` 下支持最多 3 层子文件夹：

```
.trae/rules/
├── global-rules.md
├── module-a/             # 第1层
│   └── submodule-a1/     # 第2层
│       └── sub/          # 第3层 (最深可识别)
│           └── rules.md
│           └── sub2/     # 第4层 (无法识别)
```

## 子目录规则

任何子目录可创建 `.trae/rules/`，当提及或读取该目录文件时自动应用。

## AGENTS.md / CLAUDE.md / CLAUDE.local.md

兼容这些格式。需在 设置 → 规则 → 导入设置 中开启。

- **AGENTS.md**：项目根目录，AI 行为指引
- **CLAUDE.md / CLAUDE.local.md**：Claude Code 兼容

## Commit Message 规则

`scene: git_message` 字段：

```markdown
---
scene: git_message
---
正文：生成提交信息时应遵守的规范
```

源代码管理面板 → "生成提交内容" 按钮即使用。

## 最佳实践

1. 控制单条规则粒度，保持清晰聚焦
2. 各条规则不得冲突或互覆盖
3. 使用相对路径
4. 新建/修改规则后，开全新对话
5. 若已有大量不规范代码，明确告诉 AI 当前是"重构"
