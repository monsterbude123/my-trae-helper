# 游戏原型系统

> 吸收自 CC Studio prototype 技能 + prototyper Agent（三路径 + Spike + 可证伪假设 + 强制淘汰）。

在正式生产（Phase 1+）之前，用最小成本验证核心假设。引擎无关，先原型后引擎选择。

> 协作关系：独立技能，在 kit 编排器路由下可按需加载。原型完成后产出进入 Phase 1。

## 核心铁律

```
1. 每个原型必须定义可证伪的假设
2. "2-3 concept variants > 1 concept iteration" — 自然选择胜于意志力
3. 原型代码永远不与生产代码互导入
4. 3次 PIVOT 后强制 KILL
5. 杀死的概念记录到 GRAVEYARD.md
```

## 三种验证路径

| 路径 | 可靠性 | 适合 | 限制 |
|------|--------|------|------|
| **HTML 原型** | 85-90% | 玩法验证、UI/UX 流程、逻辑规则 | 1天硬上限 |
| **Engine 原型** | 50-60% | 引擎特性验证、渲染管线、性能测试 | 2-4轮迭代正常 |
| **Paper 原型** | 100% | 规则验证、数值平衡、玩法逻辑 | 无技术依赖 |

## HTML 原型

> 纯浏览器玩法验证。无需安装引擎，最快速度验证核心循环。

```html
<!-- 60分钟 playable prototype template -->
<canvas id="game" width="800" height="600"></canvas>
<script>
// 只实现核心循环，不做 UI 润色
const ctx = canvas.getContext("2d");
// ... 你的核心玩法逻辑
</script>
```

**适用场景**: 卡牌数值、回合制逻辑、对话分支、UI 流程原型

## Engine 原型

> 目标引擎内构建最小可玩片段。不建完整项目骨架。

```
引擎原型代码放 protos/engine-proto/ (不是 src/ 或 Assets/)
允许硬编码（与生产代码的严格架构不同）
重点: 证明引擎能实现核心视觉+玩法，不是工程优雅
```

## Paper 原型

> 规则文档 + 玩测日志。最轻量、最可靠。

```markdown
# 玩法原型: {名称}
## 规则
- 玩家有 3 个行动点数
- 每个行动可移动 1 格或使用 1 张卡牌

## 玩测日志
- Round 1: 发现卡牌循环太慢，改为 2 张起始手牌
- Round 2: 移动距离改 2 格，加快节奏
```

## 可证伪假设格式

```
"如果玩家 [做X]，他们会感受到 [Y]"
"— 证据为 [可测量信号 Z]"
```

**示例**:
```
"如果玩家抽到连击卡，他们会感受到力量增长"
"— 证据为 连续 3 回合使用连击后，玩家口头报告 '爽'"
```

## 验证协议

每个原型评估 5 个维度，用分数驱动裁决（无主观判断）：

### 评分矩阵

| 维度 | 评分标准 | 权重 |
|------|---------|:---:|
| 假设检查 | 3=强烈支持 / 2=部分支持 / 1=不确定 / 0=被推翻 | ×2 |
| 最佳时刻 | 3=>2 次投入高峰 / 2=1 次 / 1=无明显高峰 / 0=从未投入 | ×1 |
| 最差时刻 | 3=无无聊段 / 2=<30s 无聊 / 1=30-60s / 0=>60s 无聊段 | ×1 |
| 意外发现 | 3=3+ 个正面意外 / 2=1-2 个 / 1=无意外 / 0=负面意外 | ×1 |
| 裁决推导 | 总分自动计算，不人工判断 | — |

总分 = 假设检查×2 + 最佳时刻×1 + 最差时刻×1 + 意外发现×1（满分 15）

### 裁决阈值

| 总分 | 裁决 | 含义 |
|------|------|------|
| **≥ 12** | ✅ PROCEED | 核心假设被强烈支持，直接进入 Phase 0 |
| **8–11** | 🔄 PIVOT | 假设部分正确，调整方向重试 |
| **7** | 🔄 PIVOT（强制限范围） | 缩小 50% 范围后重试 |
| **≤ 6** | ❌ KILL | 假设被推翻，记录 GRAVEYARD.md |
| **假设检查 = 0** | ❌ 一票否决 KILL | 无论其他维度多高，假设被推翻直接 KILL |

### 裁决记录格式

每次评估输出：
- 各维度分数 + 总分
- 裁决结果 + 理由（1 句话）
- 若 PIVOT：新假设 + 调整范围
- 若 KILL：写入 GRAVEYARD.md

## Spike Mode（4h 限时突击）

```text
--spike 模式:
  硬上限: 4 小时
  无 GDD 前置
  无关卡门禁影响
  结果: YES (可行) / NO (不可行) / PARTIAL (需进一步验证)
  适用: "这个技术方案能行吗？" "这个 API 支持我们需要的效果吗？"
```

## 强制淘汰规则

```
1 次 PIVOT:  调整假设，换路径重试
2 次 PIVOT:  警告，缩小范围
3 次 PIVOT:  强制 KILL — 概念记录到 GRAVEYARD.md
```

## 沉没成本保护

```
Concept Prototype:       > 2小时无玩法状态 → 停止
Vertical Slice:          > 第3天无完整循环 → 停止
Spike:                   > 4小时 → 停止
```

## GRAVEYARD.md 格式

```markdown
# 概念墓地

## {概念名} — KILLED {日期}
**假设**: {原始假设}
**结果**: {3轮PIVOT后的结论}
**教训**: {为什么不及预期}
**可复用**: {哪些子组件/规则可以用于未来项目}
```

## 与 Phase 1 的衔接

```
原型 PROCEED:
  → 进入 Phase 0 (引擎确认)
  → 进入 Phase 1 (剧情设计)
  → 原型代码不导入，规则/数值直接迁移

原型 KILL:
  → 记录 GRAVEYARD.md
  → 用户决定下一个概念方向
```
