# 技能包生成模板

> 蒸馏会话后生成的技能包应遵循此模板。

---

## 技能包结构

```
{skill-name}/
├── SKILL.md (核心铁律 + 骨架流程,≤150 行)
├── references/
│   ├── methodology.md (方法论详解)
│   ├── patterns.md (模式提取)
│   └── traps.md (避坑指南)
```

## 填写指南

### 1. 技能命名

```
规则:
  - 全小写 kebab-case
  - 反映核心价值而非功能列表
  - 避免 -skill/-agent 后缀

示例:
  ✅ session-distiller
  ✅ code-hygiene
  ❌ session-to-skill-converter
  ❌ distiller-skill
```

### 2. 描述编写

```
规则:
  - 一句话说明核心价值
  - 包含触发词
  - ≤ 50 字符

示例:
  ✅ "会话蒸馏器 — 从完整会话历史中提炼高质量方法论。触发词: 提炼技能、蒸馏会话"

  ❌ "这个技能可以帮助你从会话历史中整理出最佳实践和方法论..."
```

### 3. 铁律编写

```
规则:
  - 每条铁律必须可验证
  - 提供❌/✅对比示例
  - ≤ 5 条 (过多难以记忆)

示例:
  ✅ 1. 验证性 > 叙述性
       - ❌ "保持代码整洁"
       - ✅ "函数 ≤ 50 行"

  ❌ 1. 保持代码质量
       - 应该这样做...
```

### 4. 流程编写

```
规则:
  - ≤ 7 步 (过多难以执行)
  - 每步有具体动作
  - 有判定标准

示例:
  ✅ Step 1 — 意图识别
       ├─ 用户真实需求是什么?
       └─ 一次性 vs 可复用判定

  ❌ Step 1 — 首先思考一下用户的需求
```

---

> **记住**: 模板只是起点,真正的价值在于填入的内容是否**可验证、可执行、可复用**。
