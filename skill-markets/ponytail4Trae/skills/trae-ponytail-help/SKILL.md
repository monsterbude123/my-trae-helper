## 可用的三个 Skill

### trae-ponytail（写代码变懒）

**用途**：切换到懒惰高级开发模式，用最少的代码完成任务。

**加载后你的行为会变成**：
- 写代码前走决策阶梯（YAGNI → 标准库 → 平台原生 → 已有依赖 → 一行搞定 → 才写）
- 用 `ponytail:` 注释标记有意的简化
- 非平凡逻辑加一个自检
- 输出时代码先行，解释不超过三句

**触发词**："懒人模式"、"ponytail 模式"、"简化这段代码"、"用最少的代码"、"懒得写"、"能一行搞定吗"

**内容**：主 SKILL.md + 4 个参考文件 + 2 个语言指南
- 平台原生能力大全（HTML/CSS/JS API/Node.js/Python/数据库）
- 反面模式大全（20 种过度工程模式 + 正确写法对比）
- 简化示例大全（23 个真实场景的前后对比）
- ponytail: 注释约定 + 多语言自检模板
- JS/TS 指南 + Python 指南

### trae-ponytail-review（审查变精准）

**用途**：专项审查代码中的过度工程和不必复杂度。不找 Bug，只找可删除的东西。

**审查标签**：
- `删除:` 死代码、不该存在的功能 → 什么都不需要替代
- `标准库:` 手写了标准库已有的功能 → 指出标准库中的等效函数
- `原生:` 依赖做了平台原生就能做的事 → 指出原生 API
- `YAGNI:` 只有一个实现的接口/工厂/配置 → 内联或删除
- `精简:` 同样逻辑可以更少行数实现 → 给出更短写法

**审查清单**：五轮检查
1. 依赖审查（对照 16 种常见可替代依赖）
2. 抽象审查（单实现接口、单产品工厂、Builder、装饰器）
3. 文件审查（单导出文件、re-export index、碎片化）
4. 代码模式审查（深层嵌套、过度 try-catch、注释臃肿）
5. 配置审查（从来不改的环境变量和配置文件）

**输出格式**：`L<行号>: <标签> <问题>。 <替代方案>。` → 最后 `净减少: -N 行`

**触发词**："审查一下"、"有没有过度设计"、"有什么可以删的"、"review over-engineering"、"简化审查"

### trae-ponytail-debt（债不烂掉）

**用途**：扫描整个仓库，把所有 `ponytail:` 注释标记整理成技术债分类账。

**工作流程**：
1. `grep -rnE '(#|//|--) ?ponytail:' .` 扫描全仓库
2. 解析每个标记的天花板和升级路径
3. 按文件分组输出分类账
4. 标注风险：有触发条件（健康）vs 无触发条件（有腐烂风险）

**输出格式**：
```
src/services/lock.js:
  L45 | 有触发条件 | 全局锁代替细粒度锁
        天花板: 单锁保护所有账户操作
        升级:   当 QPS > 1000 时，改为按账户 ID 粒度加锁

最终统计: N 个标记, M 个无触发条件
```

**触发词**："看看技术债"、"盘点 ponytail 标记"、"有哪些简化点"、"ponytail debt"、"debt ledger"

## 典型使用流程

### 流程一：从头写功能

```
用户："用懒人模式写个搜索功能"
  → 你加载 trae-ponytail
  → 问清需求
  → 走决策阶梯：标准库有吗？平台原生有吗？...
  → 写出最简实现
  → 标注 ponytail: 注释
  → 加自检
  → 输出
```

### 流程二：重构前审查

```
用户："审查一下 src/utils 有没有过度设计"
  → 你加载 trae-ponytail-review
  → 读取目录下所有文件
  → 按五轮检查清单逐项审查
  → 输出精简建议（一行一个问题）
  → 给出净减少估算
```

### 流程三：债务盘点

```
用户："看看项目里有哪些 ponytail 标记的债"
  → 你加载 trae-ponytail-debt
  → grep 全仓库
  → 解析每个标记
  → 按文件分组输出分类账
  → 高亮无触发条件的风险标记
```

### 流程四：先审查→再动手

```
用户："这个模块太复杂了，帮我简化"
  → 你："先审查一下看哪些可以删？"
  → 加载 trae-ponytail-review → 输出建议
  → 用户确认要改的部分
  → 加载 trae-ponytail → 按最简方案逐个改
```

## 不需要用这个 skill 的情况

- 用户只是普通地让你写代码，没有提"简化"/"最简"/"懒"
- 用户在找 bug → 用 `TRAE-debugger`
- 用户在安全审查 → 用 `TRAE-security-review`
- 用户在普通代码审查（关注正确性） → 用 `TRAE-code-review`
