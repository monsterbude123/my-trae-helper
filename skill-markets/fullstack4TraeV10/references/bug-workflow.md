# Bug 工作流

> Bug 修复的轻量处理路径。发现 Bug 时触发。

---

## 快速链（Bug 修复）

```
Phase B.1: Intake(轻量)
  - 确认 Bug 可复现
  - GitNexus context() 追踪调用链，定位根因
  - 评估修复影响面（LOW/MEDIUM/HIGH）

Phase B.2: Implement
  - 🔴 RED: 写失败测试重现 Bug
  - 🟢 GREEN: 最简修复，测试通过
  - 运行全量回归，确认无新破坏

Phase B.3: Review(轻量)
  - 回归测试全部通过
  - 无新漂移产生
  - 更新模块文档（涉及接口变更时）
```

---

## 多 Bug 批量处理

多个 Bug 同时存在时：

```
1. 按严重度排序（P0 崩溃 > P1 功能异常 > P2 体验问题）
2. 逐 Bug 走快速链
3. 全量回归只跑一次（最后）
```

---

## 根因报告模板

```
Bug: {简要描述}
根因: {根本原因，非表象}
影响面: {直接 + 间接影响}
修复: {修复方式，1 句}
回归: {N} 通过 / {M} 总数
```

---

## 约束

- 根因不明不提交修复
- 涉及接口变更必须走 ADDITIVE/BREAKING 流程
- 修复后必须更新相关文档
