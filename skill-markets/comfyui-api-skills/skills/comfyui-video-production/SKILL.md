# ComfyUI 视频生产管线

端到端 ComfyUI 视频生产编排，含自动错误恢复、质量校验、实例管理。

## 快速开始：选哪条管线？

**多镜头叙事视频？**
→ **关键帧管线** — 生成关键帧 → 动画 → 拼接（带转场）

**给已有图像做动画？**
→ **I2V 批量管线** — 加载图像 → 排队 I2V → 自动校验 → 合并

**需要场景间平滑过渡？**
→ **转场管线** — 交叉淡入、运动模糊、缩放效果（通过 FFmpeg）

**ComfyUI 卡住或崩溃？**
→ **实例管理器** — 自动重启、健康检查、队列监控

**调试视频问题？**
→ **校验套件** — 检查分辨率、FPS、编解码、人脸一致性、色彩分级

## 核心管线

### 管线 1：关键帧到视频（完整叙事）

**适用**：需要多个不同镜头、故事驱动的视频

```
1. 关键帧生成阶段
   - 用 IP-Adapter/LoRA 生成一致的关键帧
   - 校验人脸一致性、光线、姿态递进
   - 保存到有组织的目录
   - 自动重试失败的生成

2. I2V 动画阶段
   - 把每个关键帧排队到 I2V 模型（Wan 2.2、LTX-2、AnimateDiff）
   - 通过 ComfyUI API 监控进度
   - 校验每个片段（分辨率、fps、时长）
   - 失败时用不同种子自动重试

3. 拼接阶段
   - 预飞校验（确保所有片段匹配）
   - 应用转场效果（交叉淡入、运动模糊）
   - 用合适编解码的 FFmpeg 编码
   - 导出含元数据的最终视频

4. 质量保证
   - 跨片段人脸一致性检查
   - 色彩分级一致性
   - 音频同步校验（如适用）
   - 生成 QA 报告
```

**预期输出**：单一连贯视频，平滑过渡。

---

### 管线 2：批量 I2V 处理

**适用**：有多个独立图像需要动画

```
1. 图像发现
   - 扫描源图像目录
   - 校验图像规格（分辨率、格式）
   - 生成处理清单

2. 并行 I2V 队列
   - 把所有图像排入 ComfyUI，配合适提示词
   - 错开提交避免过载
   - 监控队列深度与 ETA

3. 渐进校验
   - 每个视频完成立即检查
   - 标记问题（错误分辨率、fps、损坏）
   - 自动重试标记的

4. 导出与组织
   - 验证后的视频移到输出目录
   - 生成含元数据的索引
   - 创建联系表（缩略图预览网格）
```

**预期输出**：含验证后动画片段的目录。

---

### 管线 3：含转场的视频拼接

**适用**：把已有视频片段组合成专业转场

```
1. 片段校验
   - 验证所有片段存在且可读
   - 检查分辨率、fps、编解码一致性
   - 报告不匹配项与修复建议

2. 转场规划
   - 检测场景变化（cut detection）
   - 推荐转场类型（交叉淡入、缩放、平移）
   - 计算转场时间

3. FFmpeg 管线
   - 在片段间应用转场
   - 用一致设置重新编码
   - 保持质量（高码率、合适编解码）

4. 音频处理
   - 从片段提取音频（如有）
   - 转场处交叉淡入音频
   - 同步到最终视频时间线
```

**预期输出**：含无缝转场的精致视频。

## ComfyUI 实例管理

### 健康监控

```python
# 自动检测的问题：
- 队列停滞（5+ 分钟无进展）
- 内存泄漏（显存占用攀升）
- 进程崩溃（连接被拒）
- API 无响应（/queue 端点超时）
- 磁盘满（输出目录满载）
```

### 自动恢复动作

```python
1. 软恢复（不重启）
   - 清理卡住队列项
   - 强制垃圾回收
   - 卸载 VRAM 中的模型

2. 硬恢复（需重启）
   - 保存当前队列状态
   - 优雅地关闭 ComfyUI 进程
   - 等待端口释放
   - 用相同配置重启
   - 从保存状态恢复队列

3. 应急回退
   - 切换到备份 ComfyUI 实例
   - 把队列重定向到不同端口的实例
   - 不丢数据继续处理
```

### 多实例支持

```bash
# 多实例并行处理
# 端口由 .env 的 COMFYUI_URL / 启动参数指定
实例 1: ${COMFYUI_URL:-http://127.0.0.1:8188}（主 - I2V 生成）
实例 2: ${COMFYUI_URL_2:-http://127.0.0.1:8189}（次 - 放大/后处理）
实例 3: ${COMFYUI_URL_3:-http://127.0.0.1:8190}（备份 - 待命故障转移）

# 负载均衡策略：
- 轮询（等价工作量）
- 优先级（混合任务）
- 故障转移（崩溃实例）
```

## 校验套件

### 生成前校验

```python
✓ ComfyUI 运行且响应
✓ 模型已加载（UNET、VAE、CLIP）
✓ 输出目录有足够空间
✓ 源图像存在且可读
✓ 提示词非空且格式正确
✓ 工作流 JSON 合法
```

### 生成后校验

```python
✓ 视频文件存在且非零大小
✓ 分辨率匹配预期（如 768x1024）
✓ FPS 匹配预期（如 16 或 25）
✓ 时长匹配预期（如 3-5 秒）
✓ 编解码兼容（h264、h265）
✓ 无损坏（可读所有帧）
✓ 人脸一致性分数 >0.85（如角色视频）
✓ 色彩直方图在预期范围
```

### 质量指标

```python
跟踪的指标：
- 人脸嵌入距离（身份一致性）
- 光流幅度（运动平滑度）
- 帧 PSNR/SSIM（插值质量）
- 色彩直方图偏差（光线一致性）
- 音频同步偏移（如有音频）
```

## 错误处理与恢复

### 重试策略

```python
1. 随机种子重试
   - 生成失败？换种子
   - 每关键帧最多 3 次
   - 跟踪失败种子（避免重用）

2. 参数调整重试
   - CFG 过高导致伪影？降低
   - 步数过少导致不完整？增加
   - 分辨率过高 OOM？降级

3. 模型回退重试
   - Wan 2.2 14B OOM？回退到 1.3B
   - LTX-2 不可用？回退 Wan 2.1
   - AnimateDiff 动作坏？换动作 LoRA

4. 检查点恢复
   - 每个成功片段后保存进度
   - 从最近成功检查点恢复
   - 跳过已生成片段
```

## 工作流生成

当被要求创建视频生产工作流时：

1. **评估需求**
   - 镜头/关键帧数量
   - 每镜头目标时长
   - I2V 模型偏好
   - 转场风格
   - 质量 vs 速度权衡

2. **生成管线配置**
   - 基于 VRAM/质量需求的模型选择
   - 分辨率和 FPS 设置
   - 校验阈值
   - 重试策略

3. **提供执行脚本**
   - API 提交的 Python 脚本
   - 拼接的 FFmpeg 命令
   - 校验检查
   - 恢复流程

4. **监控与适应**
   - 实时跟踪进度
   - 早期检测失败
   - 应用恢复策略
   - 报告最终指标

## 最佳实践

### 关键帧视频

- 跨所有关键帧用相同种子（一致性）
- IP-Adapter 权重 0.75-0.85（强但不僵化）
- I2V 前校验关键帧（节省算力）
- 保持片段 4-8 秒（甜点）
- 用 0.5-1s 交叉淡入（平滑但不慢）

### 批处理

- 小批量处理（4-8 个同时）
- 每批后立即校验
- 每批成功后保存检查点
- 重要片段用优先级队列

### 实例管理

- 每 30s 监控队列深度
- 5 分钟无进展则重启
- 备用实例在另一端口就绪
- 记录所有重启事件以便调试
