# 门禁协议 · 三级制 + Agent 切换 + 失败处理

> 来源: 原 SKILL.md §2.1-2.5
> 加载时机: 任何阶段结束、门禁审查前

---

## 门禁三级制 (PASS / CONDITIONAL / FAIL)

```
PASS (>=85):
  → 自由进入任何其他阶段。门禁通过。

CONDITIONAL (60-84):
  → 可以继续但带标注。
  处理:
  - 标注未达标维度
  - 记录为"待改善"
  - 不阻塞其他阶段的工作
  - 在下次门禁时复查
  特例: Aesthetic >=85 但总分 <70 → "一票保留"——不强制重写，标注"需补充其他维度"

FAIL (<60):
  → 必须修复才能当作当前焦点的完成状态。
  处理:
  1. 识别阻塞项
  2. 涟漪回溯找根源
  3. 修正根源（不是修症状）
  4. 重新门禁审查
```

## 各阶段门禁标准

| 阶段 | 门禁项 | PASS | CONDITIONAL | FAIL |
|------|------|------|-------------|------|
| P0 沙盒 | 宪法可检测性 | 所有公理可检测 | 1-2条公理模糊但可修 | >=3条不可检测 |
| P0 沙盒 | 角色限制完整性 | 所有角色有限制 | 主角有限制，配角缺 | 主角无 forbidden_methods |
| P1 骨架 | 角色弧完整性 | 所有主要角色弧完整 | 次要角色弧有断裂 | 主角弧断裂 |
| P1 骨架 | 涟漪传播 | 零 BLOCKER + CRITICAL<=2 | CRITICAL 3-5且有计划 | BLOCKER>0 或 CRITICAL>5 |
| P2 剧情 | 赢面公式 | 全部 PASS | 有 BORDERLINE但可接受 | 有 FAIL |
| P2 剧情 | 伏笔覆盖度 | >=70% | 50-69% | <50% |
| P3 降噪 | 六维总分 | >=85 | 60-84 | <60 |
| P3 降噪 | 主题一致性 | 无主题断裂 | 严重偏离<=2 | 主题断裂>0 |
| P4 润色 | 伏笔回收率 | >=90% | 70-89% | <70% |
| P4 润色 | 涟漪终审 | 零 CRITICAL, HIGH<=3 | CRITICAL<=2有计划 | CRITICAL>2 |

## Agent 切换协议

当两个 Agent 的核心信条冲突时，按以下规则裁决:

```
Creative Director 质疑 Consistency Auditor 的 FAIL:
  → CD 可以提出"种子保护申请"
  → 申请必须包含: 哪个种子、为什么不能改、替代方案
  → CA 将其标记为 EXEMPTION(免除)，而非强制修复
  → EXEMPTION 必须记录在 S00 修改日志中

Consistency Auditor 质疑 Creative Director 的方向:
  → 如果是宪法违规(BLOCKER)，CA 有最终否决权
  → CD 可以提案修宪，但修宪前原宪法仍然生效
  → 如果不是宪法违规，CD 有最终裁决权（"温度>逻辑"）

两个 Agent 都不确定时:
  → 回到用户（人类 Creative Director）裁决
  → 呈现: 问题 + 两个视角 + 建议
  → 用户裁决后写入"设计决策记录"
```

## Agent 交接格式

每次 Agent 切换时必须传递:

```
=== Agent交接 ===
从: World Architect
到: Plot Orchestrator
当前阶段: P0沙盒 → P1骨架

已完成:
  - 宪法文档 (3条公理, 全部可检测)
  - 物理常量表 (8个常量)
  - 势力版图 (3个势力)
  - 角色种子 (4个核心角色)

待解决:
  - 概念注册表待初始化 (>=10概念)

下一步: 卷结构定义 + 角色弧设计
=== 交接完毕 ===
```

## 门禁失败的处理

```
门禁 FAIL → 不允许进入下一阶段

处理流程:
1. 识别阻塞项（哪个维度/哪条规则）
2. 涟漪回溯——找到根源（这个阻塞是哪个上游决策导致的？）
3. 修正根源（不是修阻塞症状，是修引发阻塞的设定）
4. 重新涟漪传播——确认修正没有引入新阻塞
5. 重新门禁审查
```
