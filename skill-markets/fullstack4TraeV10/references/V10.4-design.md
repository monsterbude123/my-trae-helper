## 1. 视觉验证升级（腐烂点 9）

### 1.1 现状（V10.3.9）

```python
# acceptance-audit.py:_audit_visual_evidence
1. PNG magic number (前 8 字节 == b'\x89PNG\r\n\x1a\n')
2. 文件大小 ≥ 5000 bytes
3. PIL 像素亮度 [30, 240] — 软警告
4. 文件活跃性 (7 天内)
```

### 1.2 问题

实战案例: 00-04-system-settings 通过三层校验,但实际布局错乱(双齿轮 + TabBar 出现系统设置 + 三层标题)。
根因: PNG 真、内容真、亮度合法,但**布局错位 + 重复元素 + 标题冗余**全部 PASS。

### 1.3 V10.4 新机制

新增 `scripts/visual-content-check.py`,在 V10.3.9 三层之上加 3 层:

| 层 | 校验 | 失败动作 |
|----|------|---------|
| L4 | PIL 解码完整(无 truncated) | 🛑 REJECT |
| L5 | 颜色直方图多样性 (unique_count ≥ N) | 🛑 REJECT (避免单色破图) |
| L6 | 关键区域非空采样 (4 象限亮度差 < 阈值 → 整页同色) | 🛑 REJECT |
| L7 (可选) | 与原型 HTML 视觉哈希对比 | ⚠️ 警告 |

`acceptance-audit.py` 的 uiux 维度在调 `_audit_visual_evidence` 之前先调 `visual-content-check.py`。
失败 = 直接 REJECT,不降级。

### 1.4 影响范围

- **新增**: `scripts/visual-content-check.py`
- **修改**: `scripts/acceptance-audit.py` 的 `_audit_uiux()`
- **门禁**: `phase-gate.py` 的 `review-to-accept` 不变(由 acceptance-audit 内部完成)

## 2. 自验自签防御（腐烂点 11）

### 2.1 现状

V10.3.9: reviewer 与 implementer 可在同一 session 中,reviewer 自评自签无意义。
实战: 主上下文自己当 reviewer,自己写 review-latest.md,自己 PASS。

### 2.2 V10.4 新机制

**Reviewer Completion Report 头部强制**:
```yaml
session_id: <uuid>          # 由 CI / 主上下文注入
self_attested: true | false  # 同一 session 完成的 = true
independently_verified_by: <other session uuid>  # 异 session 抽检的 uuid;self_attested=true 时必须填
```

**主上下文机械验证**:
```
if self_attested == true:
    1. 检查 independently_verified_by 字段非空
    2. 比对 session_id != independently_verified_by
    3. 强制二次抽检: 抽 1 个核心断言(测试通过 OR 端口 LISTEN OR 文件存在),独立命令验证
    4. 抽检失败 = REJECT
```

### 2.3 影响范围

- **修改**: `agents/reviewer.md` Completion Report 模板
- **修改**: `agents/reviewer.md` 铁律第 8 条新增"异会话验证"
- **门禁**: 主上下文新增"自验自签二次抽检"步骤(在 agent-机械验证.md Step 0.5 中体现)

## 3. Orphan Test Sweep（腐烂点 12）

### 3.1 现状

实战: SystemSettingsPage 替代 SettingsPage,但 SettingsPage.test.tsx + SettingsPage.tsx 都没即时清除。
结果: 9 failed 测试持续 1 周没人管。

### 3.2 V10.4 新机制

新增 `scripts/orphan-detector.py`:

```python
def find_orphan_tests(project_root: Path) -> list[OrphanRef]:
    """
    1. 扫描 src/**/__tests__/**/*.{ts,tsx} + tests/**/*.{ts,tsx}
    2. 对每个 .test.{ts,tsx} 文件,提取 import 语句中的目标文件路径
    3. 检查目标文件是否存在
    4. 不存在 = orphan test
    5. 额外: 扫描 src/**/*.{ts,tsx} 找 deprecated 标记 (// @deprecated, /* DEPRECATED */)
    6. 额外: 扫"旧组件"残留 — spec 提及的组件 vs 实际存在的组件
    """
```

输出 JSON: `[{test_file, missing_target, last_used_in_spec, severity}]`
退出码: 发现孤儿 = exit 1

### 3.3 使用场景

| 阶段 | 调用方 | 行为 |
|------|-------|------|
| Phase 2 (Contract) 开始 | contract-writer | 扫历史孤儿 → Plan 包含 "Delete obsolete tests" 任务 |
| Phase 3 (Implement) 末尾 | implementer | 扫本次变更引入的新孤儿 |
| Phase 4 (Review) 末尾 | rot-detector | 5 项腐化扫描之一 |

### 3.4 影响范围

- **新增**: `scripts/orphan-detector.py`
- **修改**: `agents/contract-writer.md` 铁律第 2.5 条新增 Orphan Test Sweep
- **修改**: `agents/implementer.md` 铁律第 1.5 条新增 TDD 即时
- **门禁**: `phase-gate.py` 新增 `--phase orphan-precheck`; `check_prerequisites.py` 新增同 phase

## 4. Bundle Staleness Check（腐烂点 13）

### 4.1 现状

实战: 改 TS 后 cargo build 不重触 pnpm build,frontend bundle 过期,binary chunk hash 仍是旧的。
两次踩坑,binary 内嵌的 JS chunk 名称不更新。

### 4.2 V10.4 新机制

新增 `scripts/dist-hash-check.py`:

```python
def main():
    """
    1. 检测 src-tauri/tauri.conf.json 存在 → Tauri 项目
    2. 读 src-tauri/target/release/*.exe bytes
    3. 提取所有类似 SystemSettingsPage-XXX.js 字符串(Vite chunk naming 约定)
    4. 对比 dist/assets/ 实际文件
    5. 不一致 = FAIL (binary 嵌的是旧 chunk,dist 是新 chunk)
    """
```

仅在 `src-tauri/tauri.conf.json` 存在时启用。
非 Tauri 项目: 跳过(SKIP 状态,不影响门禁)。

### 4.3 影响范围

- **新增**: `scripts/dist-hash-check.py`
- **修改**: `agents/implementer.md` 铁律第 4.5 条新增 Bundle Staleness
- **门禁**: `phase-gate.py` 新增 `--phase bundle-check`(仅 Tauri 项目)

## 5. Proactive Rot Scan（腐烂点 14）

### 5.1 现状

Agent 不主动发现问题,用户问才查。
V10.3.9 无强制腐化扫描流程。

### 5.2 V10.4 新机制

**新增 Agent**: `agents/rot-detector.md`

**新增脚本**: `scripts/proactive-scan.py`(5 项腐化扫描包)

```python
CHECKS = [
    ("orphan-tests",      run_orphan_detector),    # 腐烂点 12
    ("deprecated-code",   run_deprecated_scan),    # @deprecated / DEPRECATED 标记
    ("archive-drift",     run_archive_drift),      # 腐烂点 10 (archive 修改无回溯)
    ("bundle-staleness",  run_bundle_staleness),   # 腐烂点 13 (仅 Tauri)
    ("visual-freshness",  run_visual_freshness),   # 腐烂点 9 (视觉证据新鲜度)
]
```

每个 check 返回 `{name, status, severity, evidence}`:
- `status`: `PASS | WARN | FAIL | SKIP`
- `severity`: `PASS | WARN | FAIL`

退出码: 任一 FAIL = exit 1。

### 5.3 Phase 4.5 强制

V10.4 骨架流程新增 **Phase 4.5 (Proactive Rot Scan)**:
- 在 Phase 4 (Review) 末尾 + Phase Accept 之前
- rot-detector 强制跑 proactive-scan.py
- 任意 FAIL = 阻断 Accept,要求 implementer 修复

### 5.4 影响范围

- **新增**: `agents/rot-detector.md`
- **新增**: `scripts/proactive-scan.py`
- **修改**: SKILL.md §0 骨架流程加 Phase 4.5
- **修改**: SKILL.md §1 委派速查加 rot-detector

## 6. 新增 Constitution Articles

### Article IX — TDD 即时（Test-Update-Atomic）

> **腐烂点 12 修复**。

**Rationale**: 改实现不立即同步改测试 = 死测试复活。V10.4 强制改/删组件 → 立即改/删测试,同 PR atomic,禁止"先合实现后续 cleanup"。

**Enforcement**:
- Implementer 改实现 / 删组件 / 改接口 → 必须在同一 commit 修改对应测试
- Implementer 删除组件文件 → 必须删除对应测试文件(物理删除,非注释)
- Contract-Writer 改契约 → 必须更新 contract test 骨架
- orphan-detector.py 在 Phase 2/3/4.5 必跑,发现孤儿 = REJECT

**禁止例外**: 无。"先合实现后续 cleanup" = 禁止模式。

### Article X — 异会话验证（Cross-Session Verification）

> **腐烂点 11 修复**。

**Rationale**: 同 session 自评自签 = 自我背书,无独立验证 = 无意义。V10.4 强制异 session 验证或主上下文二次抽检。

**Enforcement**:
- Reviewer Completion Report 必须含 `session_id` + `self_attested` 字段
- `self_attested: true` 时必须填 `independently_verified_by`(其他 session uuid)
- 主上下文对 self_attested=true 必做二次抽检(独立命令验证至少 1 个核心断言)
- 抽检失败 = REJECT

**禁止例外**: 无。异 session 验证是质量底线。

### Article XI — 视觉真实验证（Real Visual Verification）

> **腐烂点 9 修复**。

**Rationale**: PNG magic + 文件大小 = 弱校验,布局错乱也 PASS。V10.4 强制视觉证据 PIL 解码 + 颜色直方图 + 关键区域采样。

**Enforcement**:
- 视觉证据必须 PIL 完整解码(无 truncated)
- 颜色直方图唯一色数 ≥ 阈值(避免单色破图)
- 关键区域非空采样(避免整页同色/全黑)
- 任一不通过 = REJECT,不允许 `--skip-visual` 绕过

**禁止例外**: 仅当 Plan 阶段显式锁定 uiux 维度为 N/A 时可跳过。

## 8. 决策表

| 设计点 | 决策 | 理由 |
|------|------|------|
| 视觉验证层数 | L4-L6 强制,L7 可选 | L4-6 解决实战问题,L7 (HTML 哈希对比) 复杂度高,降级为可选 |
