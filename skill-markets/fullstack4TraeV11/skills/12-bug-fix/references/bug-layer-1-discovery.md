# Bug 处理分层决策框架 — Layer 1 发现分层

> **V11.8.3 设计原则**：本层回答"怎么发现bug"，不规定具体模块数/路由数。项目规模决定覆盖策略，技术栈决定验证手段。

---

## 核心思维模型

```
发现分层决策树
├── 维度选择：观察哪些维度？
│   └── 通用 4D：视觉 / 行为 / 数据 / 控制台
│
├── 覆盖策略：观察多少范围？
│   ├── 冒烟覆盖：核心路由（登录/支付/主流程）
│   ├── 全量覆盖：所有公开路由 + 认证路由
│   └── 重点覆盖：本次变更影响范围
│
└── 委派决策：谁来观察？
    ├── 小规模（≤6 路由）：主代理亲自
    └── 大规模（>6 路由）：拆 sub-agent 并行
```

---

## §L1.1 维度选择（通用 4D）

| 维度 | 观察内容 | 失败对应 |
|------|----------|----------|
| **视觉** | 截图含期望关键字/图标/配色；布局未塌缩 | L3 视觉走样 |
| **行为** | CTA 触发期望动作；路由跳转带 query | L2 局部不可用 |
| **数据** | 列表非空；i18n 翻译；字段完整 | L2/L3 |
| **控制台** | 0 error / 0 401-500 / 0 hydration mismatch | L2（API 类）|

**决策铁律**：单维度不可证伪。必须多维度交叉验证。

---

## §L1.2 覆盖策略决策表

| 项目阶段 | 推荐覆盖 | 理由 |
|---------|---------|------|
| 新功能开发 | 重点覆盖（变更范围） | ROI 最高 |
| 发布前回归 | 冒烟覆盖（核心路由） | 时间有限 |
| 大版本升级 | 全量覆盖 | 变更面大 |
| Bug-hunt 专项 | 全量覆盖 + 认证路由 | 彻底暴露 |

**认证路由特殊处理**：受 auth 保护的路由，必须先走登录态获取流程（技术栈决定具体步骤）。

---

## §L1.3 委派决策

```
IF 路由数 ≤ 6:
    主代理亲自观察（4D × N 串行）
    
IF 路由数 > 6:
    拆 sub-agent 并行
    每组 ≤ 5 路由（避免 sub-agent 上下文溢出）
    
IF 单个路由观察时间 > 预算 / 路由数:
    降低维度（视觉 + 控制台 2D）或 委派
```

---

## §L1.4 发现层产出

| 产出 | 用途 | 下一层 |
|------|------|--------|
| 原始观察日志 | 证据存档 | Layer 2 分层 |
| Bug 候选清单 | 待分类队列 | Layer 2 严重性判定 |
| 截图证据 | 视觉证据 | Layer 3 修复验证 |

---

## 反模式

| # | 反例 | 问题 |
|:--:|------|------|
| L1-1 | 只截图不读可见文本 | 假证据风险（登录态异常） |
| L1-2 | 单维度判定 PASS | 不可证伪 |
| L1-3 | 全量覆盖时主代理亲自串行 | 效率浪费 |
| L1-4 | 认证路由未登录就截屏 | middleware 重定向误导 |
