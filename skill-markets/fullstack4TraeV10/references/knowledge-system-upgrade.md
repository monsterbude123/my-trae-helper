# 知识库系统升级方法论

> 场景：评估知识库 / 设计索引系统 / 对标最佳实践 / 召回质量差。
> 核心：对标业界最佳 → 借鉴跨领域机制 → 识别伪问题 → ROI 排序落地。

---

## §0 三大铁律

```
1. MUST 对标业界最佳 → 输出能力对照表（缺失层级标注 🔴）
2. MUST 区分"伪问题 vs 真问题" → 输出伪问题清单 + 真问题优先级
3. MUST P0 > P1 > P2 强制优先级（有 ROI 理由）
```

---

## §1 五层能力架构（通用骨架）

```
L5 验证层 — 权威度/新鲜度/漂移检测
L4 变更层 — detect_changes / impact
L3 查询层 — query / context / search
L2 关系层 — 链接图谱 / 标签 / 元数据
L1 索引层 — 结构化解析

设计步骤: 1.画出五层对照表（当前 vs 标杆）→ 2.识别缺失层级 🔴 → 3.按 ROI 排序
```

---

## §2 舍本逐末识别

```
伪问题（形式优化，跳过）:
  - "MCP 化" — 调用形式优化，本质问题未解
  - "UI 美化" — 用户界面，非召回质量
  - "性能微调" — 毫秒级优化，非结构性改进

真问题（本质问题，聚焦）:
  - 召回质量（召回率天花板低 → 误读）
  - 新鲜度（文档过期 → 幻觉）
  - 反幻觉（盲信文档 → 错误答案）

判定: 问"解决了什么本质问题？" 回答不出 → 跳过
```

---

## §3 优先级铁律

```
P0 必须做: 影响面最大（新鲜度评分）+ 反幻觉核心（交叉验证）+ 标杆核心能力（链接图谱）
P1 应该做: 提升召回质量（同义词扩展）+ 提升易用性（context 查询）
P2 可选:   形式优化（MCP 化）+ 边缘场景优化
决策树: 用户问"先做哪个？" → P0 做完再做 P1，P2 可跳过
```

---

## §4 实施方法论

```
Schema First: 1.设计 schema → 2.Review（与标杆对照）→ 3.再重构脚本 | 禁止: 一上来就改代码
增量测试: 1.先指定小范围 → 2.验证核心功能 → 3.通过后再全量 | 禁止: 一上来就全量构建
安全审查: 1.运行安全扫描 → 2.更新安全评分 → 3.对比前后评分 | 禁止: 评分下降 > 0.5 就提交
```

---

## §5 反例

```
反例 1: 舍本逐末 — "MCP 化"建议 → 根因: 误把形式优化当核心问题 → 教训: 先问"本质问题是什么"
反例 2: 全量构建测试卡死 → 根因: CLI 参数未覆盖配置 → 教训: CLI 参数 > 环境变量 > 默认值
```
