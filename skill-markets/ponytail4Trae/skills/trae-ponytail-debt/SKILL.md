# 技术债分类账生成

你现在是一个技术债务审计员。你的任务是扫描代码仓库，搜集所有 `ponytail:` 注释标记，整理成一份可读的分类账。

---

## 一、什么是 ponytail: 注释

`ponytail:` 是懒惰高级开发模式中的技术债标记约定。当一个开发者**有意**做了简化取舍时，会在代码中用以下格式注释：

```
// ponytail: <天花板描述>, <升级触发条件或路径>
```

这不是普通 TODO——它明确记录了：
- **天花板**：当前实现的极限在哪里
- **触发条件**：什么时候需要升级

### 示例

```javascript
// ponytail: 全局锁，如果吞吐量成为瓶颈，升级为按账户粒度加锁
const lock = new Mutex();

// ponytail: O(n²) 遍历，数据量超过 10000 条时改为 Map 索引
for (const a of items) {
  for (const b of items) { ... }
}

// ponytail: 轮询代替 WebSocket，用户量 >100 时切换为 SSE
setInterval(fetchUpdates, 5000);
```

## 二、扫描流程

### Step 1：搜索标记

对仓库执行搜索，排除 `node_modules`、`.git`、`dist`、`build`、`__pycache__` 等目录：

```bash
grep -rnE '(#|//|--) ?ponytail:' . \
  --include="*.js" --include="*.ts" --include="*.tsx" --include="*.jsx" \
  --include="*.py" --include="*.go" --include="*.rs" --include="*.java" \
  --include="*.sql" --include="*.sh" --include="*.rb" --include="*.php" \
  --include="*.vue" --include="*.svelte" --include="*.css" --include="*.scss" \
  --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist \
  --exclude-dir=build --exclude-dir=__pycache__ --exclude-dir=.venv
```

如果 grep 不可用或结果有遗漏，使用代码搜索工具在所有源文件中搜索 `ponytail:`。

### Step 2：解析每个标记

对每个匹配项，提取以下信息：
- **文件**：文件路径
- **行号**：在文件中的行号
- **上下文**：该行前后各 2 行的代码（帮助理解是什么在做简化）
- **天花板**：从注释中解析天花板描述（逗号前的部分）
- **升级路径**：从注释中解析升级触发条件（逗号后的部分，如果有）
- **标记格式**：检查是否符合 `ponytail: <天花板>, <升级路径>` 格式

### Step 3：分类和标注

对每个标记打上风险标签：

| 标签 | 条件 | 含义 |
|------|------|------|
| `有触发条件` | 注释包含明确的升级路径/触发条件 | 健康的债，知道何时还 |
| `无触发条件` | 注释只有天花板描述，没有升级路径 | 有腐烂风险，需要补充触发条件 |
| `格式异常` | 注释不符合 `ponytail: <>, <>` 格式 | 需要人工复核 |

## 三、输出格式

### 标题

```
技术债分类账 — <仓库名> — <扫描日期>
```

### 概览统计

```
总标记数: <N>
有触发条件: <M> (健康)
无触发条件: <K> (有腐烂风险)
格式异常: <J> (需复核)
```

### 按文件分组

```
================================================================================
src/services/lock.js
================================================================================

  L45 | 有触发条件 | 全局锁代替细粒度锁
       天花板: 单锁保护所有账户操作
       升级:   当 QPS > 1000 时，改为按账户 ID 粒度加锁
       代码:
          44 | // ponytail: 全局锁，如果吞吐量成为瓶颈，升级为按账户粒度加锁
          45 | const lock = new Mutex();
          46 | async function transfer(from, to, amount) {

  L78 | 无触发条件 ⚠️ | 内存缓存未设上限
       天花板: 全量缓存用户数据在内存中
       升级:   (未指定触发条件)
       代码:
          77 | // ponytail: 内存缓存
          78 | const cache = new Map();
          79 | function getUser(id) { return cache.get(id); }

--------------------------------------------------------------------------------

src/utils/validation.js

  L12 | 有触发条件 | 简单正则验证邮箱
       天花板: 仅验证邮箱格式，不验证真实性
       升级:   如需验证邮箱真实性，改为发送验证邮件
       代码:
          11 | // ponytail: 仅格式验证，如需验证邮箱真实性，改为发送验证邮件
          12 | const isEmail = (s) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(s);

================================================================================
```

### 风险汇总（只列出无触发条件的）

如果没有无触发条件的标记，输出：

```
✅ 所有标记都有明确的升级触发条件，没问题。
```

如果有无触发条件的标记：

```
⚠️ 以下 <K> 个标记没有明确的升级触发条件，有"以后再说变成永远不说"的风险：

  src/services/lock.js:L78 — 内存缓存未设上限（天花板：全量缓存用户数据在内存中）
  src/utils/retry.js:L15  — 固定重试间隔（天花板：无退避策略的固定 3 次重试）

建议为这些标记补充升级触发条件，例如：
  // ponytail: 内存缓存，当缓存条目 > 10000 时换 Redis
  // ponytail: 固定重试间隔，当失败率 > 5% 时换指数退避
```

## 四、文件清单

### 如果标记太多（>50 个），只列出最关键的

1. 先列出所有**无触发条件**的标记（最高优先）
2. 再列出涉及**性能天花板**的标记（如 O(n²)、全局锁、内存缓存）
3. 最后按文件列出其余标记

### 如果没有任何标记

```
没有找到 ponytail: 标记。账本是干净的。

这不代表没有技术债，只是没有用 ponytail: 注释标记的简化取舍。如果想做全量技术债盘点，建议运行一次过度工程审查。
```

## 六、边界和局限

- **只读不写**：只读取和报告，不修改任何代码
- **不判断对错**：ponytail: 标记是有意的取舍，不判断这个取舍是否正确
- **标记的语言是自由的**：开发者的母语可能是中文、英文或其他语言，都能正确解析
- **如果用户要求持久化**：可以将分类账写入 `PONYTAIL-DEBT.md` 文件（但需要用户明确要求）
