# 工作流：Spec & Plan

> TRAE Work 提供两种工作流以应对不同复杂度的开发任务。

## Spec 工作流

面向**复杂系统级任务**。AI 生成完整三阶段文档组，存储在 `.trae/specs/` 目录（按任务名称分组为独立文件夹）：

| 文档 | 作用 |
|------|------|
| `spec.md` | 大纲 |
| `tasks.md` | 任务列表 |
| `checklist.md` | 验收清单 |

> 可对文件做版本控制，作为项目知识资产长期保留。

### 使用场景

| 场景 | 为什么需要 Spec |
|------|----------------|
| 从零搭建新系统/模块 | 需求范围大、架构决策多，必须先对齐大纲 |
| 大规模重构 / 技术栈迁移 | 涉及大量文件和模块间依赖，需清晰任务拆解和验收标准 |
| 多人协作项目 | Spec 文档作为单一事实来源对齐所有人 |
| 高质量/高稳定性项目（核心业务逻辑、支付、安全模块） | 需要详尽验收清单确保每个环节达标 |
| 需长期维护的项目 | Spec 文档留存为知识资产，降低维护成本 |

### 启用

- 输入 `/` → 选 **Spec**
- 输入 `/spec` → 回车

> 文档首次创建时 AI 暂停执行并等待确认；可直接编辑或让 AI 据指令修改。确认后，任务列表和验收清单状态随执行进度自动更新。

---

## Plan 工作流

适用于**中小型功能开发和模块级重构**。AI 分析需求 → 规划任务 → 在 `.trae/documents/` 生成 `plan.md` → 确认后逐一执行。

### 启用

- 输入 `/` → 选 **Plan**
- 输入 `/plan` → 回车

> 若生成的计划不符合预期，可手动编辑或让 AI 据指令自动调整。

---

## 内置命令一览

| 命令 | 作用 |
|------|------|
| `/plan` | 调用计划模式 |
| `/spec` | 调用规范模式 |
| `/browser_use` | 使用 browser_use 工具操作内置浏览器并获取上下文，辅助智能体进行功能验证 |
