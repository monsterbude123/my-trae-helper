# 双源校验流程（Dual-Source Flow）

> Stage 1.5 Prototype 核心流程。设计稿 + 代码原型双源必走校验，输出一致才能进入 Stage 2 Contract。

---

## 流程图

```
[spec.md AC 列表]
   ↓
[Step 1] 加载设计稿（Figma / Sketch / 截图）
   ↓
[Step 2] 加载代码原型（最小可运行 demo）
   ↓
[Step 3] 双源截图比对（设计稿 vs 代码）
   ↓
[Step 4] GAP 标注 + 修复（详见 prototype-code-gap.md）
   ↓
[Step 5] 产出 prototype.md + prototypes/ 目录
```

---

## Step 1：加载设计稿

**目标**：从 designer-handoff 包中加载设计稿，确保源材料完整。

**必含**（designer-handoff 4 件套）：
- 设计稿（Figma / Sketch 链接或 PNG / PDF 导出）
- 交互说明（hover / active / focus 状态定义）
- 设计 token（颜色 / 间距 / 字号）
- 边缘情况（loading / error / empty 三态）

**输出**：`design-source/` 目录含 1 张主截图 + 交互说明 markdown。

## Step 2：加载代码原型

**目标**：在 `prototypes/` 目录下构建最小可运行 demo。

**要求**：
- 每个 UI 元素必标 `data-ac="AC-{N}"` 属性（反向追溯 AC ID）
- 截图工具：Playwright `page.screenshot()` 锁定 viewport
- 必跑：dev server 启动 → 访问原型页 → 截图归档

**输出**：`prototypes/{change-id}/screenshot.png` + `prototypes/{change-id}/index.html`。

## Step 3：双源截图比对

**目标**：像素级比对 design-source/ vs prototypes/，识别 GAP。

**工具**（推荐 Python PIL）：
```python
from PIL import Image, ImageChops
design = Image.open("design-source/main.png")
code = Image.open("prototypes/{change-id}/screenshot.png")
diff = ImageChops.difference(design, code)
diff.save("prototypes/{change-id}/diff.png")
# diff.getbbox() 返回首个差异包围盒，None = 一致
```

**判定**：
- `diff.getbbox() is None` → 通过，进 Step 5
- `diff.getbbox() is not None` → 存在差异，进 Step 4

## Step 4：GAP 标注 + 修复

**GAP 类型**（3 类，详见 prototype-code-gap.md）：

| GAP | 含义 | 处置 |
|-----|------|------|
| 设计稿有 / 代码无 | 设计师设计了但代码未实现 | 补代码原型 |
| 设计稿无 / 代码有 | 代码多余 | 移除 / 标注"待设计" |
| 两者都有但不一致 | 颜色 / 间距 / 交互不同 | designer-handoff 澄清 |

**修复后回到 Step 3 重比**，直到 `diff.getbbox() is None`。

## Step 5：产出 prototype.md

**输出文件**：`docs/specs/changes/{change-id}/prototype.md`

**必含字段**：
- 设计稿链接 + 截图归档路径
- 代码原型路径 + `data-ac` 标注清单
- 双源比对结果（PASS + diff bbox=None 截图）
- GAP 修复记录（如有）
- 关联 AC 清单

## 反例

### 反例 A：设计稿与代码脱节（引 anti-patterns/01）

```
prototype-agent: 截一张代码截图 → 写 prototype.md "UI 已对齐设计稿"
                          ↑ ❌ 未加载设计稿，无对比基准
正确: 双源都加载 → PIL ImageChops 像素比对 → diff.getbbox() is None 才 PASS
```
详见 [anti-patterns/01-design-code-mismatch.md](../anti-patterns/01-design-code-mismatch.md)。

### 反例 B：跳过双源校验（引 anti-patterns/02）

```
spec-writer: 看一眼 Figma 截图 → 写 spec.md AC → 直接进入 Stage 2 Contract
                          ↑ ❌ 违反铁律 4 NEVER 跳过双源
正确: UI 改动必走 Step 1-4 全流程，产出 prototype.md 才能进 Stage 2
```
详见 [anti-patterns/02-skip-dual-source.md](../anti-patterns/02-skip-dual-source.md)。
