# goal-mode 强门禁研究报告

> 研究日期：2026-08-14
> 研究方法：联网调查 GitHub 多源交叉验证
> 数据来源：agent-completion-gate / make-no-mistakes / ProtocolForge 等 8 个项目

---

## 一、核心结论

**goal-mode 能做成强门禁。** GitHub 上已有 3 个成熟开源项目验证了"把目标变成机械门禁"的可行性和具体实现路径。

关键洞察：
- 当前 goal-mode 是**软执行**（prompt-based，agent 可以选择跳过）
- 强门禁需要**机械执行**（code-enforced，agent 物理上无法绕过）

---

## 二、GitHub 现状：三种强门禁范式

| 项目 | 版本 | 核心机制 | 与 goal-mode 的关系 |
|------|------|---------|-------------------|
| [agent-completion-gate](https://github.com/zhjai/agent-completion-gate) | v0.4.3 | 状态机 `in_progress → candidate_complete → [外部验证器] → complete/blocked` | **直接互补** — README 明确 "Works with /goal"，gate 补 /goal 缺失的外部产物验证 |
| [make-no-mistakes](https://github.com/momomuchu/make-no-mistakes) | v0.13.0 | 三铁律：不举证不准说完成 / 作者不审自己 / 不能失败的检查不是检查。测试篡改检测 + ed25519 签名清单 | **同构** — 与 goal-mode 的"执行≠审计"铁律完全一致，但补了机械执行层 |
| [ProtocolForge](https://github.com/gitstq/protocolforge) | v1.0.0 | YAML 协议 + Hook 门控。`stop` 阶段 = 门禁，不满足条件直接 block | **架构参考** — 提供 hook-based gate 的最小实现范式 |

## 三、关键洞察："gate vs rule/skill/memory"

agent-completion-gate README 精确总结：

> - A **rule** is advisory — a goal rationalizes past it.
> - A **skill** can be skipped — the agent chooses not to invoke it.
> - **memory** records belief, not verified truth.
> - Only a **gate the agent can't edit, on a path it can't skip, reading artifacts it can't fake** reliably stops "looks done but isn't."

当前 goal-mode 的本质：skill（可被跳过）+ prompt（advisory）。

要变强门禁：加一层 agent **物理上无法绕过**的机械执行层。

---

## 四、当前 goal-mode 的缺口分析

| 当前机制 | 类型 | 可被绕过？ |
|---------|------|-----------|
| SKILL.md 六步审计协议 | prompt/rule | ✅ Agent 可跳过审计直接说"完成" |
| goal-auditor 子代理审计 | skill delegation | ✅ Agent 可不委派 auditor，自己声称 |
| 虚假完成 3 次升级 | prompt-based counting | ✅ Agent 可不在 prompt 中计数 |
| 门禁级联重验 | prompt-based | ✅ Agent 可跳过重验 |
| 阻塞检测 3 turn | prompt-based | ✅ Agent 可提前标 blocked |

**结论：全部是"advisory"，没有一层是"mechanical"。**

## 五、强门禁设计方案

### 5.1 状态机（四态）

```
in_progress -> candidate_complete -> [外部验证器] -> complete / blocked
     └────────> blocked (needs-review / missing evidence)
```

- **in_progress**：Agent 正常工作
- **candidate_complete**：Agent 声称完成，只能写这个状态（写 `complete` 会被 gate 拒绝）
- **complete**：仅外部验证器脚本可写入，需全部验收项 PASS
- **blocked**：验收失败，Agent 返回工作

### 5.2 新增文件结构

```
skill-markets/goal-mode/
├── gate/                         # 新增 - 机械执行层
│   ├── verify-goal.py            # 外部验证器（python3 -E）
│   ├── acceptance_manifest.yaml  # 验收清单（人类编写）
│   └── STATE_MACHINE.md          # 状态契约
├── state/                        # 新增 - 运行时状态
│   └── completion_candidate.yaml # Agent 只能写 candidate_complete
└── references/
    └── strong-gate-design.md     # 设计文档
```

### 5.3 验收清单格式

```yaml
goal: "{用户原始目标}"
checks:
  - id: file_exists_check
    type: file_exists
    path: "{产物路径}"
  - id: test_pass_check
    type: command_exit_zero
    command: "pytest tests/ -v"
  - id: content_verify
    type: contains_string
    path: "{文件}"
    substring: "{期望内容}"
review_items: []
```

### 5.4 外部验证器核心逻辑

```python
#!/usr/bin/env python3 -E
"""Agent 无法编辑此文件（受 CODEOWNERS 保护）。只读真实产物。"""
import sys, yaml, subprocess, os

def main():
    manifest = yaml.safe_load(open("gate/acceptance_manifest.yaml"))
    candidate = yaml.safe_load(open("state/completion_candidate.yaml"))
    
    if candidate["status"] != "candidate_complete":
        print("BLOCKED: Agent 未提议 candidate_complete")
        sys.exit(1)
    
    failures = []
    for check in manifest["checks"]:
        # 逐项验证真实产物...
        if not passed:
            failures.append(check)
    
    if failures:
        print(f"BLOCKED: {len(failures)} 项未通过")
        sys.exit(1)
    else:
        print("COMPLETE-OK")
        candidate["status"] = "complete"
        yaml.dump(candidate, open("state/completion_candidate.yaml", "w"))
        sys.exit(0)
```

### 5.5 Gate 接线

| 层 | 机制 | 复用 |
|----|------|------|
| **Guard** | `scripts/goal-mode-guard.py` 校验 state 不被篡改为 `complete` | 项目已有 guard 模式 |
| **Gate (L1)** | `.husky/pre-commit` 加 `python gate/verify-goal.py` | 项目已有 pre-commit |
| **Gate (L3)** | `.github/workflows/skill-market-gate.yml` 加 goal gate required check | 项目已有 CI |

### 5.6 门禁解除

```
1. 验收清单全 PASS -> verify-goal.py 写 complete
2. .husky/pre-commit 检测到 state == complete -> 跳过 gate 检查
3. commit 后 state/completion_candidate.yaml 可清理或归档
4. 下一个目标重新初始化 gate
```

## 六、安全不变量

从 agent-completion-gate + make-no-mistakes 提炼：

| # | 不变量 | 实现 |
|---|--------|------|
| 1 | gate/manifest/inventory 受保护 | `.husky/CODEOWNERS` 标注，Agent 不可编辑 |
| 2 | 验证器只读真实产物 | `verify-goal.py` 不读 state 的 claim |
| 3 | 未知项 fail-closed | 无 check 的 surface = blocked |
| 4 | 唯一完成信号 | gate verdict 是唯一 `complete` 来源 |
| 5 | 产物内容是敌对数据 | 验证器用确定性检查，不把产物当指令 |
| 6 | 禁止环境注入 | `python3 -E` 执行 |

## 七、与 Claude Code /goal 的关系

agent-completion-gate 明确指出：

> `/goal` decides *when to keep going*; the gate decides *what counts as done* - by reading real artifacts.

强门禁方案让 goal-mode 同时拥有：
- **自主循环**（已有）：六步审计 + 子代理编排
- **产物验证**（新增）：外部验证器读真实文件，补齐 `/goal` 缺失的"读真实产物"能力
