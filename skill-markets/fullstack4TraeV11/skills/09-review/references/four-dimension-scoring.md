# 4 维评分算法（Four-Dimension Scoring）

> Stage 4 Review Step 3 必走。V10 reviewer 铁律 2 + acceptance-gates-v10.md 蒸馏。

---

## 4 维度

| 维度 | 权重 | 评分项 |
|------|:---:|--------|
| **代码层** | 25% | 单元测试 + Contract 测试 + Lint 0 error + 覆盖率 ≥90% + 无 TODO/FIXME |
| **API 层** | 30% | 真实端点非 mock + 接口签名 100% 一致 + 数据模型 100% 一致 + 错误码 100% 一致 |
| **UI/UX 层** | 25% | 视觉一致性 + 交互逻辑 + UI 细节（6 项检查清单） |
| **模块边际** | 20% | GitNexus impact + 下游无副作用 + 文档同步 + 扩展点标注 |

---

## 评分公式

```
总分 = (通过维度 / 适用维度) × 5.0
- 任一维度 0 分 = 🛑 REJECT
- 总分 ≥ 4.0 才 PASS
- N/A 不计入分母（避免灰色术语）
```

### 示例

| 维度 | 通过 | 适用 | 分数 |
|------|:---:|:---:|:---:|
| 代码 | ✓ | ✓ | 5.0 |
| API | ✓ | ✓ | 5.0 |
| UI/UX | ✓ | ✓ | 5.0 |
| 边际 | ⚠️ | ✓ | 3.5 |

总分 = (3+0.7+0+0.7) / 4 × 5.0... 实际按权重计算。

---

## N/A 处理

- 不可验证 → 标 N/A + 明确理由（如 CLI 项目无 UI 层）
- N/A 不计入分母
- 灰色术语（"基本通过"/"大致完成"）禁

---

## 反例

### 反例 A：凑分

```
代码 3.0 / API 4.0 / UIUX 2.5 / 边际 3.0 → 总分 3.1  # ❌ 凑分
正确: 任一维度 0 分 = REJECT，不接受"凑到 ≥4.0"
```

### 反例 B：N/A 充数

```
代码 / API / UIUX / 边际 全标 N/A → 适用维度 = 0 → 分数 = N/A  # ❌
正确: 不可验证才 N/A + 必填理由
```

### 反例 C：维度遗漏

```
只评代码 + API → 跳过 UIUX + 边际  # ❌
正确: 4 维必评（适用维度全评）
```
