# 视觉验收工作流

> 触发条件：新功能涉及 UI、页面改版、E2E 测试通过后、发版前 UI 回归。
> 核心原则：**截一帧，看一帧。禁止批量操作后统一审查。**
> 工具：vision-audit 技能 + screenshot 技能

---

## §0 验收通道选择决策树

```
需要视觉验收？
  │
  ├── 单页面、1~3 步操作、快速诊断 → 通道 A：AI 直读 PNG
  │     工具: Read 工具加载截图
  │     适用: 小改动验证、疑难诊断
  │     局限: 无结构化 JSON、精度低于专用 VL
  │
  ├── 多页面、需结构化报告、发版前回归 → 通道 B：vision-audit
  │     工具: screenshot skill + vision-audit --single
  │     产出: 结构化 JSON（含 diagram/zones/risk/verdict/issues）
  │
  ├── 已有录制好的走查脚本 → 通道 C：直接跑 walkthrough
  │     工具: walkthrough.mjs
  │
  └── vision-audit 不可用（本地 VL 模型缺失/环境异常）
        ├── 降级为通道 A（AI 直读）
        └── 但标记为「降级验收」，发版前回归必须补通道 B
```

---

## §1 验收三阶段

| Phase | 内容 | 每步操作 | 异常处理 |
|-------|------|---------|---------|
| 1 页面级 | 每个路由截图，确认加载完整 | 截图 → vision-audit 分析 → 确认无异常 | 页面空白/500 → 检查后端日志和网络请求 |
| 2 交互级 | 逐元素点击，每步截图审查 | 点一个按钮 → 截图 → 分析 → 记录结果 → 下一步 | 点击无响应 → 检查元素是否可交互、JS 错误 |
| 3 边界态 | 空态/错误态/加载态/极限数据 | 停后端测错误态，清数据测空态，大数据量测性能 | 边界态无法触发 → 确认触发方式，必要时 mock 接口 |

## §2 大脑—眼球流水线（操作铁律）

```
大脑 (AI) ──决策──→ 眼球 (screenshot) ──点+截──→ 视觉皮层 (vision-audit) ──报告──→ 大脑 ──循环
```

### 每步操作协议

```
1. AI 读当前截图/报告 → 分析布局、文字、交互状态
2. AI 决定下一个操作（点哪个元素）
3. 执行 1 个操作（点击/输入/等待）
4. 立即截图
5. 截图送 vision-audit 分析
6. 读分析结果 → 记录 → 回到步骤 1
```

### 禁止行为对照

| 禁止 | 后果 | 替代 |
|------|------|------|
| 一次点所有按钮再截图 | 中间态不可追溯，出了问题不知道哪步 | 一次只做一个操作 |
| 不看截图就继续下一步 | 基于错误假设操作，累积错误 | 每步截图后用 vision-audit 审查 |
| "布局合理，无异常" 式废话 | 无法定位问题 | 描述实际文字、按钮状态、内容是否预期 |
| 不看后端日志就断言前端问题 | 错判根因 | 每步检查后台日志和网络请求 |

## §3 验收报告模板

```markdown
## 视觉验收报告 — <页面名>

| Step | 操作 | 截图 | 分析结果 | 状态 |
|------|------|------|---------|------|
| 1 | 导航到 {路由} | p1.png | {vision-audit verdict} | 🟢/🟡/🔴 |
| 2 | 点击 "{按钮文字}" | p2.png | {vision-audit verdict} | 🟢/🟡/🔴 |

### 结论: 🟢 通过 / 🟡 MEDIUM（有缺陷但不阻塞）/ 🔴 HIGH（阻塞发版）

### 问题清单
- [ ] {问题描述} — {截图编号} — {严重程度}
```

## §4 视觉分析输出协议

vision-audit 输出 JSON 格式（AI 读报告时对照此协议理解）：

```json
{
  "diagram": "用 ┌┐└┘├┤│┬┴┼─ 画页面布局，标出实际文字和按钮",
  "zones": {
    "titlebar": "顶栏文字和按钮",
    "left_panel": "左侧区域内容",
    "center": "中心区域实际文字",
    "right_panel": "右侧面板内容",
    "bottom_panel": "底栏内容",
    "statusbar": "状态栏信息"
  },
  "risk": "LOW / MEDIUM / HIGH",
  "verdict": "一句话描述当前交互状态",
  "issues": ["问题1", "问题2"]
}
```

| 字段 | AI 如何使用 |
|------|-----------|
| `diagram` | 一眼看清页面结构，决定下一个操作点哪个区域 |
| `zones` | 逐区域确认内容是否符合预期 |
| `risk` | 决定继续往下走还是停下来修 |
| `verdict` | 快速理解当前页面处于什么交互状态 |

## §5 异常降级协议

| 异常 | 降级方案 | 恢复条件 |
|------|---------|---------|
| vision-audit 不可用（模型缺失） | 通道 A：AI 直读 PNG，人工判断 | 安装 VL 模型后恢复通道 B |
| 截图工具不可用 | 尝试 Chrome DevTools MCP 截图 | 修复 Playwright 环境后恢复 |
| 后端服务不可达 | 记录异常，跳过依赖后端的页面 | 后端恢复后补验 |
| 特定页面渲染异常（非本次改动） | 标记为「已知问题」+ 截图，不阻塞本次验收 | 分离报告，不混入本次改动回归 |
| 交互后页面状态与预期不符 | 🔴 标记 HIGH，输出：预期状态 vs 实际状态 + 截图对比 | 修复后重新验收该步骤 |
