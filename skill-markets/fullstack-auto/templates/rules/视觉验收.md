# 视觉验收规则 — 功能/页面 UI 审查标准流程

> 触发条件：新功能开发完成、页面改版、E2E 测试通过后、发版前 UI 回归。
> 版本：v1.2　更新：2026-06-26

## §0 验收架构：截一帧，看一帧

| 场景 | 方式 | 口诀 |
|------|------|------|
| 复杂跨页面流程 | browser-use Agent | 自主完成 |
| 逐步精细诊断（推荐） | 大脑-眼球流水线 | 截一帧看一帧 |
| 精确 CSS 断言 | screenshot skill | 选择器精确 |
| 已有固定走查脚本 | walkthrough 脚本 | 直接跑 |

**模型配置**（`.env.vision`）：
```bash
VISION_MODEL_NAME=qwen3-vl-8b-instruct    # ~10s/张
# VISION_MODEL_NAME=qwen3.6-35b-a3b-mtp    # ~90s/张，高质量
```

### §0.5 备选通道：AI 直接 Read PNG 解读

当 AI 主模型支持图像输入时，可跳过本地 VL 模型，直接用 `Read` 工具加载 PNG。
适用：1~3 张图快速诊断、vision-audit 不可用时降级兜底。
局限：无结构化 JSON、精度低于专用 VL 模型。
**铁律**：发版前 UI 回归 / 验收报告归档 → 必须走 vision-audit 产出 §4 格式 JSON。

## §1 验收三阶段

| Phase | 内容 | 方式 |
|-------|------|------|
| 1 页面级 | 每个路由截一帧全貌，确认加载完整 | `screenshot <route> out/p1.png` → `vision-audit --single` |
| 2 交互级 | 逐元素点击，每步截图审查 | 大脑-眼球流水线逐帧 |
| 3 边界态 | 空态/错误态/加载态/极限数据 | 停后端测错误态，清数据测空态 |

## §4 视觉分析输出协议（AI Agent 必读）

```json
{
  "diagram": "用 ┌┐└┘├┤│┬┴┼─ 画页面布局，标出实际文字和按钮",
  "zones": {
    "titlebar": "顶栏文字和按钮",
    "left_panel": "左侧菜单/树节点",
    "center": "中心区域实际文字（对话/编辑/表格）",
    "right_panel": "右侧面板（文件树/检查器/Skills）",
    "bottom_panel": "底栏标签和内容",
    "statusbar": "状态栏信息"
  },
  "risk": "LOW",
  "verdict": "一句话描述当前交互状态",
  "issues": []
}
```

| 字段 | 用途 |
|------|------|
| `diagram` | 一眼看清页面结构，决定点哪个区域 |
| `zones` | 逐区域对比 spec 预期 |
| `risk` | 决定继续还是阻塞 |
| `verdict` | 快速理解交互状态 |

## §5 大脑-眼球流水线（操作铁律）

**截一帧，看一帧。**

```
大脑 (Trae) ──决策──→ 眼球 (screenshot) ──点+截──→ 视觉皮层 (vision-audit) ──报告──→ 大脑 ──循环
```

- **大脑**：读 vision-audit 报告，看 ASCII 布局图，判断当前状态，决定下一步
- **眼球**：一次点一个按钮，截一张图。用 `screenshot skill`，不用 Chrome DevTools MCP
- **视觉皮层**：`vision-audit --single <截图>`，本地 VL 模型分析
- **铁律**：截一帧看一帧。禁止批量操作后统一审查

### 禁止行为

| 禁止 | 替代 |
|------|------|
| 一次点击所有按钮再截图 | 一次只做一个操作 |
| 不看截图就继续 | 每步截图后用 vision-audit 审查 |
| "布局合理，无异常" 式废话 | 描述实际文字、按钮状态、内容 |
| 用 Chrome DevTools MCP 截图 | 用 Playwright screenshot skill |
| 不看后台日志就断言 | 每步检查后台日志和网络请求 |

```

```
