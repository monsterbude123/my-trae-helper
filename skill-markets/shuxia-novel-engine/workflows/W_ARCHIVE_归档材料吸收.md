# W_ARCHIVE · 归档材料吸收

> 场景: 用户提供历史版本/先行实验/旧讨论中的归档文件，要求吸收有价值设定到当前项目
> 主导: Creative Director（分类决策） + Consistency Auditor（门禁验证）
> 正交于 P0-P4 流水线。任何阶段都可能触发。

---

## 触发条件

| 信号 | 示例 |
|------|------|
| 归档材料 | "这个是我去年12月的先行版本..." / "这些设定是否有必要吸收" |
| 材料审查 | "这个讨论文档里的设定..." / "从底层开始吸收" |
| 补充吸收 | "注意存疑的地方进行讨论" / "完成吸收的文档按照示例重命名" |

---

## 四阶段流程

### 阶段A: 全量分析 & 四类分流

```
你的任务: 逐条对照归档材料 vs 当前项目设定，将每条内容分入四类之一。

必须重新读取当前项目相关文件来确定状态——不能凭记忆判断。
```

#### 四类分流表

| 分类 | 标记 | 含义 | 后续操作 |
|------|------|------|---------|
| **Ⅰ. 已吸收** | ✅ | 当前项目中已存在的设定，完成度相当或更高 | 不操作 |
| **Ⅱ. 可吸收（无争议）** | ➕ | 当前项目缺失、但可直接写入的价值点 | 直接吸收 |
| **Ⅲ. 需讨论（存疑点）** | ⚠️ | 有价值但可能与当前方向冲突，或存在多选方案 | 通过 AskUserQuestion 确认 |
| **Ⅳ. 不适用** | ❌ | 与当前方向明确冲突、已废弃的技术路径、或已被更优方案替代 | 不吸收，计入"不适用百分比" |

#### 分类判断原则

```
Ⅰ 已吸收:
  - 当前项目中存在同名概念/设定/角色 → 直接✅
  - 核心逻辑相同但表述更修真化 → 视为✅（术语升级不算丢失）
  - 当前版本完成度更高 → ✅，不需要"退回"旧版本

Ⅱ 可吸收:
  - 当前项目明确缺失该维度的设定 → ➕
  - 与宪法公理/角色锚点无冲突 → ➕
  - 补充的是"执行细节"（如开发瓶颈/失败迭代）→ ➕
  - 属于"世界观深度补充"（如制度层级/系统性解释）→ ➕

Ⅲ 需讨论:
  - 与当前设定存在结构性差异（如敌人层级/设备介入程度）→ ⚠️
  - 存在多个合理方案需要选择 → ⚠️
  - 引入新角色类型（会影响全卷骨架/角色关系网）→ ⚠️
  - 设备/功法等涉及"物理可行性边界"判断 → ⚠️

Ⅳ 不适用:
  - 已被当前版本明确替代的旧方案 → ❌
  - 与宪法公理冲突（如"无限灵力""魔法般觉醒"）→ ❌
  - 旧版本的篇幅规划（如15章结构 vs 当前180+章结构）→ ❌
  - 纯写稿参考性质的氛围描写（不入正式文档）→ ❌
```

#### 输出格式

向用户呈现分析结果时，使用以下格式：

```
## {文件名} 吸收评估

### Ⅰ. 已吸收（N项）
| 内容 | 当前落点 |
|------|---------|
| xxx  | xxx.md §N |

### Ⅱ. 可吸收（N项）
→ 计划落点：xxx.md / 新建 xxx.md
| 内容 | 计划落点 | 说明 |
|------|---------|------|

### Ⅲ. 需讨论（N项）
→ 通过 AskUserQuestion 逐项确认
（列出每个存疑点的选项和影响）

### Ⅳ. 不适用（N项）
→ 不吸收原因简述
```

### 阶段B: DOC FIRST 影响面评估

```
确认吸收范围后，进入 DOC FIRST 门禁（AGENTS.md §零）。

步骤:
1. 列出所有将要修改/新建的文件清单
2. 对每个变更，查影响面速查表（AGENTS.md §二）确认修复层级
3. 确定 S10 注册表中需要新增的概念条目
4. 确认 check.py 基线（运行前先记录当前得分）

任意一项未确认 → 🛑 禁止开始编辑。
```

#### 影响面速查（本工作流专用）

| 变更类型 | 典型影响 | 修复层级 |
|---------|---------|---------|
| 补充世界观设定 | 目标文档 + S10 | L1→L3 |
| 新增科技树节点 | 科技树.md + 版本迭代 + 装备量化（如有） | L1 |
| 补充势力制度 | 势力版图.md + S10 | L1→L3 |
| 新建角色 | 角色档案 + 人物关系图 + 骨架（如影响主线）+ S10 | L1→L2→L3 |
| 新建装备/设备 | 科技树.md 或 装备法器量化.md + S10 | L1→L3 |

### 阶段C: 执行吸收

```
按顺序执行:
1. 先处理Ⅱ类（可吸收无争议）——批量编辑
2. 再处理Ⅲ类（用户已确认的存疑点）——逐项编辑
3. 每完成一个文件的编辑，立即记录变更

编辑规则:
- 优先编辑现有文件，不新建冗余文件
- 新建设定文件遵循现有命名约定
- 新建角色文件遵循人物档案模板格式（基础→域属→量化→性格→关系→主题→审查）
- 所有新概念必须锚定灵场物理——有经典物理原型+L场对接
```

---

### 阶段D: 门禁验证 & 归档标记

#### D1. S10 注册表更新

```
为每个吸收的内容新增概念条目:
- 世界观补充 → category: worldbuilding
- 科技树节点 → category: equipment / technique
- 新角色 → category: character
- provenance 统一标记为 experimental_2512 或对应的实验代号
```

#### D2. check.py 验证

```
运行: python skill-novel-engine/scripts/check.py --mode score
要求: 100/100 PASS，零新增问题
不通过 → 修复 → 重跑 → 直到通过
```

#### D3. 归档文件重命名

```
根据吸收比例选择标记:
┌─ 100% 吸收（四项分类中无Ⅲ/Ⅳ）→ filename☑️.md
├─ 95%+ 吸收（有少量不适用）→ filename⚠️(X%不适用).md
└─ 部分吸收（还有内容待处理）→ 保持原名，等待下次处理

重命名方式: 文件系统 Rename-Item（非 git mv）
```

## 反模式与常见错误

| 错误 | 纠正 |
|------|------|
| 凭记忆判断"已有" | 必须重新读取当前项目文件确认 |
| 把术语升级当成"丢失" | "AI编译器"→"外物证道+小真"是进化，不是丢失 |
| 跳过 DOC FIRST 直接编辑 | 任何编辑前必须先列影响面 |
| 跳过 S10 注册表 | 每次吸收必须更新注册表 |
| 不讨论直接吸收存疑点 | Ⅲ类必须先 AskUserQuestion |
| 创建冗余新文件 | 优先在现有文件中补充，不新建 |
| 吸收时破坏现有设定的完整性 | 新内容必须与宪法公理/角色锚点对齐 |

## 完整示例

> 参考本工作流在项目中的实际执行记录：
> - `归档/实验2512/07_剧情策划/背景材料☑️.md` — 100%吸收示例
> - `归档/实验2512/deepseek讨论/世界构建☑️.md` — 100%吸收示例
> - `归档/实验2512/07_剧情策划/辅助材料⚠️(5%不适用).md` — 95%吸收示例（气氛营造细节不入正式文档）

---

> **维护规则**: 吸收比例判断标准—Ⅰ类占比=已吸收、Ⅱ+Ⅲ类占比=本次吸收、Ⅳ类占比=不适用。不适用比例>20%时考虑是否需要重新评估分类标准。
