# §9 度量指标体系

> 没有度量的验收是宗教，没有验收的度量是装饰。指标体系让验收从"凭感觉"变成"看数据"。

---

## 核心指标矩阵

| 指标 | 定义 | 健康阈值 | 采集方式 |
|------|------|---------|---------|
| **测试通过率** | passed / (passed + failed) | ≥ 99% | CI 报告 |
| **测试确定性分数** | 1 - (flaky_count / total) | ≥ 99.5% | 重复跑 10 次统计 |
| **Mock 覆盖率** | 已 mock 的外部依赖 / 总外部依赖 | 100% | 静态分析 + 人工标注 |
| **P0 路径 E2E 覆盖率** | 关键用户路径有 E2E 的比例 | 100% | 路径清单核对 |
| **诊断闭环时长** | 异常发现 → 修复 → 验证完成 | < 30 min（B）/ < 1 day（A）| 时间戳日志 |
| **门禁通过率** | 一次通过门禁的 PR 比例 | ≥ 80% | CI 统计 |
| **验收债务条目数** | 已记录的例外 / skip / xfail | 单调下降 | 看板统计 |
| **平均测试耗时** | 全量测试总耗时 / 用例数 | < 100ms | `--durations` |

## 测试确定性分数（Flaky Score）

**计算方式**：同一测试在相同 commit 上连跑 10 次，统计通过 / 失败次数。

```
确定性分数 = (通过次数 / 10) × 100%

10/10 = 100% → 确定性测试
8/10  = 80%  → Flaky，必须修复
5/10  = 50%  → 严重 Flaky，立即 skip 并立 issue
```

**自动化脚本**：
```bash
# CI 夜间任务：对全量测试跑 10 次，输出 Flaky 清单
for i in {1..10}; do
  pytest --junitxml=results-$i.xml
done
python scripts/flaky_score.py results-*.xml > flaky-report.md
```

## Mock 覆盖率

**问题**：测试代码里有 `monkeypatch.setattr`，但漏 mock 的依赖照样发真实网络请求。Mock 覆盖率就是衡量"该 mock 的都 mock 了吗"。

**实现思路**：
1. 维护一份"外部依赖清单"（LLM / DB / Redis / 第三方 API / 文件系统）
2. 静态分析测试代码，提取所有 mock 点
3. 计算 `已 mock 的外部依赖 / 清单总数`

**简单版**：在 autouse fixture 里 hook 网络层，任何未 mock 的真实请求都打 warning。

```python
@pytest.fixture(autouse=True)
def detect_unmocked_network(monkeypatch):
    """检测未 mock 的网络请求"""
    import socket
    real_socket = socket.socket
    def guard(*args, **kwargs):
        raise AssertionError(
            f"测试尝试真实网络连接！请检查 mock 是否完整。"
            f"socket args: {args}"
        )
    monkeypatch.setattr("socket.socket", guard)
```

## 诊断闭环时长

```
异常发现时间 T1（截图 / 日志告警）
  → 根因定位时间 T2
  → 修复提交时间 T3
  → 验证通过时间 T4

诊断闭环时长 = T4 - T1

健康范围：
  Workflow B（即时诊断）：< 30 分钟
  Workflow A（批量回归）：< 1 个工作日
```

## 验收债务看板

类似技术债务，验收债务也需要可视化：

| 类型 | 条目 | 风险 | 责任人 | 计划还债时间 |
|------|------|------|-------|-------------|
| 例外 | auth 模块 skip 了 2 个测试 | 中 | alice | 2026-07-15 |
| xfail | 性能测试未达基线 | 高 | bob | 2026-07-01 |
| 跳过 | E2E 未覆盖支付回调 | 高 | carol | 2026-07-10 |
| TODO | 安全 checklist 未完成 | 中 | dave | 2026-07-20 |

**铁律**：债务条目数必须单调下降。任何新增债务必须有明确的还债时间，否则不允许新增。
