# 亚文化宪法编写指南

> 版本: v1.0 · 日期: 2026-06-16 · 来源: skill-novel-engine/references/

> 如何为你的虚构世界定义不可违反的铁律
> 通用模板——适用于任何亚文化创作项目

---

## 什么是宪法

宪法公理 = 你的世界不可违反的铁律。它们不是"创作指导"——它们是**类型系统**。每条公理定义了合法操作的类型边界。

## 公理的数量

- 最少 3 条，最多 7 条
- 少于 3 条 → 约束不足，引擎无法有效检查
- 多于 7 条 → 约束过多，创作空间被窒息

## 公理的写法

每条公理包含四部分：

```yaml
- id: 1
  name: "公理的短名（4-8 字）"
  statement: "公理的完整陈述（一句话）"
  allows: "允许的操作类型"
  forbids: "禁止的操作类型（具体可检测的关键词或模式）"
  severity: 8  # 违反时的严重度 1-10
```

### 示例（科幻）

```yaml
- id: 1
  name: "光速不可超越"
  statement: "信息/物质的传播速度不超过真空中光速"
  allows: "量子纠缠/虫洞（如果定义了例外）"
  forbids: "超光速航行/实时跨星系通信（未定义例外时）"
  severity: 10
```

### 示例（奇幻）

```yaml
- id: 1
  name: "魔法等价交换"
  statement: "任何魔法效果必须有等价的能量/物质/寿命代价"
  allows: "献祭/蓄能/借力——只要代价被量化"
  forbids: "无代价施法/凭空创造/无限魔力——除非有明确定义的例外"
  severity: 9
```

### 示例（言情）

```yaml
- id: 1
  name: "情感递进不可跳级"
  statement: "角色关系的每次重大转变必须有触发事件铺垫"
  allows: "慢热/爆发/误会——只要触发事件成立"
  forbids: "一见钟情无事铺垫/突然反目无动机/冷漠→深爱在一次对话后"
  severity: 7
```

## 公理的质量检查

每条公理必须通过以下检查：

1. **可检测性**: AI 能否从文本中判断是否违反？
2. **非冗余性**: 是否可以由其他公理推导？（如果可以 → 删除）
3. **可量化性**: 是否有明确的"违反"边界？
4. **叙事价值**: 违反公理是否会影响故事品质？（如果不影响 → 公理太弱）

## 常见错误

| 错误 | 为什么不对 | 正确做法 |
|------|-----------|---------|
| 公理太长（>2 句话） | 难检测 | 拆成多条 |
| 公理太模糊（"魔法是神秘的"） | 不可检测 | 写成可量化的规则 |
| 公理写成了创作建议（"主角应该成长"） | 不是约束 | 写成"主角在卷五前不可直接修炼" |
| 公理写成了剧情（"最终BOSS是XX"） | 不是规则 | 写成"最终BOSS的力量来源必须在卷二揭示" |
