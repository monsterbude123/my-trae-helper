# Bug 处理分层决策框架 — Layer 4 收敛分层

> **V11.8.3 设计原则**：本层回答"何时停止"，是防止范围蔓延的关键。时间预算驱动 + 严重性清零判断。

---

## 核心思维模型

```
收敛分层决策树
├── 停止条件：什么时候结束？
│   ├── 正常结束：L1 + L2 清零
│   ├── 预算结束：时间耗尽，上报剩余
│   └── 阻断结束：发现无法修复的 L1
│
├── 产物落盘：留下什么？
│   ├── Bug 单：所有发现 + 状态
│   ├── e2e 测试：回归资产
│   └── 截图证据：版本控制
│
└── 遗留处理：未修完怎么办？
    ├── 延后 L3：下迭代处理
    ├── 上报 L1：阻断升级
    └── 记录 L2：backlog
```

---

## §L4.1 停止条件决策表

| 条件 | 动作 | 产出 |
|------|------|------|
| **L1 + L2 清零** | 正常结束 | 完整报告 |
| **时间预算耗尽** | 统计剩余，上报 | 部分完成报告 |
| **发现无法修复的 L1** | 立即阻断上报 | 5 字段阻塞报告 |
| **修复引入新 L1** | 切回 Wave 1 | 继续修复 |

---

## §L4.2 时间预算管理

```
初始预算分配:
    发现阶段: 20%
    修复阶段: 60%（Wave 1: 30%, Wave 2: 20%, Wave 3: 10%）
    收敛阶段: 20%

预算耗尽判定:
    IF 剩余时间 < 单个 L1 修复预估:
        立即停止，上报剩余清单
        
预算动态调整:
    IF Wave 1 用完 30% 预算仍未清零:
        上报阻断，不继续 Wave 2
```

## §L4.4 遗留处理策略

### 按 severity 处理

| Severity | 遗留处理 | 上报级别 |
|----------|---------|---------|
| L1 阻断 | 立即上报，不结束 | P0 阻断 |
| L2 不可用 | 记入 backlog，下迭代优先 | P1 延后 |
| L3 视觉 | 记入 backlog，按优先级排期 | P2 |
| L4 体验 | 可不记录 | - |

### 阻断上报格式（5 字段）

```
🛑 阻断: {阻断原因}
缺什么: {具体缺失}
影响范围: {哪些功能受影响}
尝试过: {已尝试的方案}
建议: {下一步建议}
```

```markdown
### 遗留清单
| Bug ID | Severity | 状态 | 建议处理 |
|--------|----------|------|---------|
| BUG-NNN | L2 | OPEN | 下迭代优先 |

### 时间消耗

- 修复: Y min
- 回归: Z min
- 总计: T min

### 产物清单
- Bug 单: N 个
- e2e 测试: M 个
- 截图: K 张
```

## §L4.6 收敛层决策流程

```
1. 统计当前 L1/L2/L3 数量
2. 检查时间预算
3. 判定停止条件:
   IF L1 + L2 = 0:
       正常结束，生成完整报告
   ELIF 预算耗尽:
       统计剩余，生成部分报告
   ELSE:
       继续修复
4. 落盘产物
5. 处理遗留
```

## 反模式

| # | 反例 | 问题 |
|:--:|------|------|
| L4-1 | 预算耗尽继续修 | ROI 低，耽误其他任务 |
| L4-2 | L1 未清零就结束 | 核心功能仍有阻断 |
| L4-3 | 产物散落不归档 | 证据丢失，无法追溯 |
| L4-4 | 遗留不上报 | 隐患隐藏 |

## 与 V11.8.2 的差异

| 项目 | V11.8.2 | V11.8.3 |
|------|---------|---------|
| 停止条件 | 无显式定义 | 预算驱动 + severity 清零 |
| 时间预算 | 无 | 分阶段预算分配 |
| 遗留处理 | 隐式 | 显式分类 + 上报 |
| 阻断上报 | 无流程 | 5 字段标准化 |
