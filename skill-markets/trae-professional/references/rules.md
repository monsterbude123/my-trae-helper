# 规则（Rules）

> 通过制定规则规范 AI 在 TRAE Work 内的行为（代码风格、语言与框架、交互方式等），使输出更符合个人偏好与项目要求。

## 应用场景

- **提升效率**：将个人经验和项目要求转化为可复用规则 → 减少沟通成本和人工审校时间
- **统一标准**：将团队规范、项目标准结构化为规则 → 避免偏差
- **保障质量**：让 AI 明确项目核心约束（架构设计、命名规范、代码风格）

## 规则类型与目录

| 类型 | 存储位置 |
|------|----------|
| **全局规则** | `~/.trae-cn/user_rules`（macOS/Linux），`%userprofile%/.trae-cn/user_rules`（Windows） |
| **项目规则** | 项目内 `.trae/rules/` |

> 规则 vs 技能：规则**全量加载**（对话开启即注入并持续占用上下文）；技能**按需加载**。

## 运行环境

| 环境 | 适用任务 | 适用客户端 |
|------|----------|------------|
| **本地** | 仅本地任务 | 桌面版 |
| **云端** | 仅云端任务 + GitHub 项目 | 网页版 + 桌面版 |

## 创建全局规则

1. 头像 → **设置** → **规则**
2. (仅桌面版) 选择运行环境：本地 / 云端
3. **创建** → 输入规则 → **保存**

## 创建项目规则

### 方式一：手动创建
在 `.trae/rules/` 下创建 Markdown 文件 → 写入规则 → 保存

### 方式二：导入外部规则
兼容以下项目根目录文件（**仅桌面版支持**）：
- `AGENTS.md` — 跨工具通用项目规则
- `CLAUDE.md` / `CLAUDE.local.md` — Claude Code 项目规则

生效步骤：
1. 规则文件放项目根目录（`CLAUDE.md` / `CLAUDE.local.md` 在项目迁移时自动带入）
2. **设置 → 规则**
3. **导入设置** → 打开 **"将 AGENTS.md 包含在上下文中"** 和 **"将 CLAUDE.md 包含在上下文中"** 开关

## 最佳实践

- 控制单条规则的内容粒度，保持清晰、聚焦、易理解
- 各条规则之间不冲突、不相互覆盖
- 文件路径用相对路径（相对项目根目录）
- 引用规则时优先选与当前对话/任务强相关的
- 新建/修改规则后开启全新对话，避免历史上下文冲突
- 项目中已有大量不规范代码时，AI 可能沿用现有风格：
  - 明确说明当前任务为"重构"
  - 特定场景强制 AI 严格遵循新规则
  - 启动专门重构项目，逐步提升整体代码质量

## 示例规则（参考）

**基础交互**
- 所有回答使用中文表述
- 代码关键逻辑和易理解困难的部分添加中文注释
- 代码超过 20 行优先考虑抽象或聚合

**通用编码**
- 避免不必要对象复制或克隆
- 避免多层嵌套，提前返回
- 使用适当并发控制机制

**重构**
- 每次只做一个小改动，然后测试
- 频繁提交，保持代码随时可工作
- 重构前确保有足够测试，每次修改后运行测试

**代码可读性**
- 使用有意义、描述性名称，遵循项目/语言约定
- 函数只做一件事，保持适当抽象层次
- 注释解释"为什么"而非"做什么"

**性能优化**
- 避免不必要对象创建、及时释放资源、注意内存泄漏
- 避免重复计算、使用适当数据结构、延迟计算
- 识别可并行化操作，避免不必要同步
