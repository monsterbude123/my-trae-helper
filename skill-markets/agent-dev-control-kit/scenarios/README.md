# Agent Dev Control Kit — 场景指南

> 本目录提供 agent-dev-control-kit 的典型使用场景和工作流指南，帮助开发者在实际项目中快速应用控制体系。

---

## 场景总览

| 场景编号 | 场景名称 | 适用阶段 | 核心产出 |
|:-------:|---------|---------|---------|
| 01 | [新项目建立控制体系](./01-new-project-setup.md) | 项目初始化 | 完整控制体系骨架 |
| 02 | [添加新 Execution Skill](./02-add-new-execution-skill.md) | 功能扩展 | 新的执行控制技能 |
| 03 | [定制 Guard 检查规则](./03-customize-guards.md) | 规则定制 | 定制化守卫规则 |
| 04 | [门禁失败排查流程](./04-troubleshooting-gate-failure.md) | 故障排查 | 问题诊断报告 |
| 05 | [遗留项目迁移](./05-migrate-legacy-project.md) | 项目改造 | 渐进式迁移方案 |

## 如何选择场景

### 按项目阶段选择

```
项目阶段：
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  新项目启动  │───▶│  功能开发   │───▶│  运维维护   │───▶│  项目改造   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
       │                  │                  │                  │
       ▼                  ▼                  ▼                  ▼
  场景 01            场景 02/03          场景 04             场景 05
  新项目建立          添加技能/           故障排查            遗留迁移
  控制体系            定制规则
```

### 按问题类型选择

| 问题类型 | 推荐场景 |
|---------|---------|
| 新项目如何建立质量门禁？ | 场景 01 |
| 新功能需要新的控制流程？ | 场景 02 |
| 现有规则过于严格/宽松？ | 场景 03 |
| 门禁检查失败，如何排查？ | 场景 04 |
| 老项目如何引入控制体系？ | 场景 05 |

## 场景之间的关系

### 依赖关系

```
场景 01（新项目建立）
     ↓
     ├─→ 场景 02（添加新技能）←──┐
     │                           │
     ├─→ 场景 03（定制规则）←────┤
     │                           │
     └─→ 场景 04（故障排查）←────┘
                                   ↑
                                   │
场景 05（遗留迁移）────────────────┘
```

### 协作关系

- **场景 01 → 场景 02/03**：建立基础体系后，根据业务需求扩展技能和规则
- **场景 02/03 → 场景 04**：新增技能或规则后，可能触发门禁失败
- **场景 05 → 场景 02/03**：遗留项目迁移后，可能需要定制化规则

## 场景核心产出物

### 场景 01 产出物

```yaml
新项目建立控制体系:
  目录结构:
    - .agents/skills/           # Execution Skills
    - gates/                    # 门禁配置
    - guards/                   # 守卫脚本
    - hooks/                    # Git Hooks
    - scripts/                  # 辅助脚本
  
  配置文件:
    - gate-config.json          # 门禁配置
    - guard-config.json         # 守卫配置
    - hooks-config.json         # Hooks 配置
  
  文档:
    - README.md                 # 项目控制体系说明
```

### 场景 02 产出物

```yaml
添加新 Execution Skill:
  技能文件:
    - .agents/skills/{skill-name}/SKILL.md
  
  参考文档:
    - 使用 templates/execution-skill-template.md
    - 参考 references/execution-skills-guide.md
  
  测试用例:
    - 至少 1 个完整执行流程示例
```

### 场景 03 产出物

```yaml
定制 Guard 检查规则:
  守卫脚本:
    - guards/{guard-name}-guard.mjs
  
  白名单配置:
    - guard-config.json 中的 whitelist 字段
  
  测试验证:
    - 本地测试通过
    - CI 集成测试通过
```

### 场景 04 产出物

```yaml
门禁失败排查:
  诊断报告:
    - 失败原因分析
    - 影响范围评估
    - 修复建议
  
  修复产物:
    - 代码修复 / 配置调整
    - 回归测试结果
```

### 场景 05 产出物

```yaml
遗留项目迁移:
  迁移计划:
    - 现状评估报告
    - 渐进式迁移路线图
  
  迁移产物:
    - 迁移后的控制体系
    - 兼容性处理方案
    - 迁移验证报告
```

## 快速导航

### 按角色选择

| 角色 | 推荐场景 | 理由 |
|------|---------|------|
| 项目负责人 | 场景 01、05 | 负责体系建立和项目改造 |
| 开发工程师 | 场景 02、03 | 负责技能开发和规则定制 |
| 运维工程师 | 场景 03、04 | 负责门禁维护和故障排查 |
| 质量工程师 | 场景 04、05 | 负责质量门禁和迁移验证 |

### 按时间投入选择

| 时间预算 | 推荐场景 | 说明 |
|---------|---------|------|
| ≤ 30 分钟 | 场景 04 | 快速排查门禁失败 |
| 1-2 小时 | 场景 02、03 | 添加技能或定制规则 |
| 半天 | 场景 05（评估） | 遗留项目迁移评估 |
| 1-2 天 | 场景 01、05（实施） | 新项目建立或遗留迁移实施 |

## 使用建议

### 首次使用者

建议按以下顺序阅读：

1. 先读 [场景 01](./01-new-project-setup.md) 理解控制体系全貌
2. 根据实际需求选择场景 02-05 深入学习
3. 参考 `references/` 下的详细指南获取完整规范

### 有经验使用者

- 直接跳转到目标场景文件
- 参考 `templates/` 下的模板快速应用
- 遇到问题时回到对应场景查阅排查步骤
