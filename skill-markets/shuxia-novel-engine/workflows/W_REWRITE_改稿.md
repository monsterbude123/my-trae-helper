# W_REWRITE · 改稿工作流

> 场景: 用户说"这一章/这一段重写"或"这个方向不对，换一种写法"
> 不同于 W_BRAINSTORM（改设定），改稿是"设定不变，换叙事方式"

---

## 触发条件

- "这一章重写"
- "这段写得太..."
- "换一种写法试试"
- "节奏不对"
- "感觉不对"

---

## 改稿循环

### Step 1: 诊断

```
运行 evaluate.py --chapter N → 看哪个维度最低
运行 combat_narrative.py / drama_narrative.py → 专项问题
问用户: "你感觉哪里不对？" (不要猜)
```

### Step 2: 保留/丢弃

```
和用户确认:
  保留: 哪些必须保留？(信息揭示/角色状态推进/伏笔操作)
  丢弃: 哪些可以重新来？(描写方式/对话风格/场景顺序)
```

### Step 3: 重写

```
基于保留的"硬内容"(信息/状态/伏笔)重写
换叙事方式(描写/对话/节奏)
必要时枚举不同写法的候选:
  enumerate.py --chapter N --count 3
```

### Step 4: 对比验证

```
旧版 evaluate → 旧分
新版 evaluate → 新分
如果新分 < 旧分 → 警告用户，可能是改坏了
如果新分 > 旧分 → 确认替换
```

---

## 改稿原则

- **不要全盘否定旧版**: 旧版一定有写得好的部分。改稿是手术，不是炸楼。
- **优先修最弱维度**: 如果 World 65/Aesthetic 90，修 World 不要动 Aesthetic 部分。
- **一次改一章**: 改一章验证一章，不要"全都重写"然后发现全都不行。
