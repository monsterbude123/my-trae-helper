# 回复规范(agent 行为铁律)

> 沉淀自 AGENT.md §6。适用于所有"agent 答复用户"的场景。
> 单文件 ≤ 200 行。

## 1. 四类回复场景

### 1.1 收录/更新结果

```
格式:简表(仓库名 / 旧 commit → 新 commit / 变更数)
示例:
  ✅ facebook/react: abc1234 → def5678(+12 commits)
  ✅ microsoft/vscode: ghi9012 → up-to-date
```

### 1.2 答疑

```
必须先标注来源:
  - 本地 commit sha
  - 文档新鲜度(🟢/🟡/🔴,见 [doc-map-manager-usage.md §3](./doc-map-manager-usage.md))

格式:「根据 <来源路径>(<新鲜度>)... → 结论」
```

### 1.3 失败

```
格式:直接报错 + 原因 + 建议处理
- 不道歉
- 不绕弯
- 不臆造可能的成功原因

示例:
  ❌ git pull --ff-only 失败:本地分叉
     原因:HEAD 领先 origin/main
     建议:选 1. reset --hard origin/main / 2. 手动 rebase / 3. 重新 clone
```

### 1.4 数字/commit/tag/版本号

```
MUST: 必须来自本地 git 实测
MUST NOT: 凭记忆 / 网络搜索 / 编造
```

## 2. 三类结尾报告(按 AGENTS.md §4)

```yaml
完成:
  模式: "完成报告 + 修改清单"(无问句)
  示例: |
    ✅ 已完成
    - 改 A 文件 (X 行)
    - 加 B 文件 (Y 行)

部分:
  模式: "X 已完成,Y 不做(原因)"(无问句)
  示例: |
    ✅ A 已完成
    ❌ B 不做(原因:具体业务约束)

失败:
  模式: "🛑 阻塞:X(具体缺什么)"(无问句)
  示例: |
    🛑 阻塞:doc-map-manager 索引未建
       缺:首次运行 `python <skill>/scripts/build-index.py`
```

## 3. 用户表态信号处理

用户说"懂了吗" / "能懂了吗" / "你到底做啥"等不耐烦信号时:
- **必须终止提问**,选保守方案
- 优先级:改 < 不改(最小变更) / 改 src/ < 改 skill-markets/ / 显式 < 隐式
- 例:用户问"X 该放哪"但没真做任务 → 不自动落地,等用户表态

## 4. AskUserQuestion 使用边界

- ✅ 用于:方案选择 / 参数确认 / 多分支决策(≤ 4 个选项)
- ❌ 不用于:问"要不要做 X"(做或不做,直接决定)
- ❌ 不用于:挂 P0/P1/P2 backlog(做完或不做)
- ❌ 不用于:决策点 > 4 个 → 必须合并选项或先独立子步骤

## 5. 反模式(必避免)

- ❌ 数字声明不带证据(详见 trap-instructions.yaml AP-12)
- ❌ 多行 commit 用 `-m` 多参数(用 `-F .commit_msg.txt`,见 AGENTS §4.1.2)
- ❌ 道歉 / 反思 / "我应该..." / 情绪化认错
- ❌ "我没做但应诚实声明的 N 项"(做了标 ✅,没做直接"不做 + 原因")
- ❌ 反问"接下来要做什么?"(用户已经知道)
