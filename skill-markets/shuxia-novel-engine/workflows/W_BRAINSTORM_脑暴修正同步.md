# W_BRAINSTORM · 用户脑暴修正 → 系统同步

> 正交于 P0-P4 流水线。任何阶段都可能触发。
> 主导: Creative Director + Consistency Auditor

---

## 触发条件

用户在对话中发出以下任一信号：

| 信号 | 示例 |
|------|------|
| 修正设定 | "其实林岳不应该..." / "我改主意了" / "这里不对" |
| 新增设定 | "需要新增一个角色..." / "应该还有一个..." |
| 逻辑漏洞 | "这个逻辑bug太重了" / "他几乎不可能跑" |
| 信息同步 | "先同步这个信息" / "我说一下..." |
| 方向调整 | "我原本的设计是..." / "和我想的不一样" |

---

## 五阶段流程

### 阶段A: 理解修正意图

```
你的任务: 用你自己的话复述用户的新设定，确认理解正确。

检查清单:
□ 新设定是什么？（一句话）
□ 旧设定是什么？（如果存在）
□ 新旧之间的差异是什么？
□ 这个修正是澄清(细化)、新增(新实体)、还是修改(覆盖)？
□ 用户有没有隐含的假设？（比如"林岳不用监控"隐含"所有修真者都不用科技"）

如果任何一项不确定 → 追问用户，不要猜测。
```

### 阶段B: 影响面分析

```
你的任务: 计算这个修正的全部影响面。从 L0 开始。

步骤:
1. 查 创作正文/世界观/亚文化四层索引.md → 定位新设定所属层级
2. 如果在 L0（宪法公理）→ 最高优先级。任何公理修改都触发全局涟漪。
3. 如果在 L1（角色/势力/科技树）→ 检查:
   - 角色: allowed_methods/forbidden_methods 是否需要更新？
   - 势力: 势力关系是否需要更新？
   - 科技树: 节点定义/依赖关系是否需要更新？
4. 如果在 L2（剧情/伏笔）→ 检查:
   - 全卷骨架是否需要同步？
   - 伏笔是否受影响？
   - 叙事扩散线是否受影响？
5. 如果在 L3（章节正文）→ 检查:
   - 哪些章节的哪个场景受影响？
6. 运行 ripple.py 输出完整影响面清单

输出格式:
  影响面清单
  L0: [文件1, 文件2, ...] — 改动类型
  L1: [文件1, 文件2, ...] — 改动类型
  L2: [文件1, 文件2, ...] — 改动类型
  L3: [文件1, 文件2, ...] — 改动类型
  预计总文件数: N
  严重度: BLOCKER=0 / CRITICAL=N / HIGH=N / MEDIUM=N
```

### 阶段C: 与用户确认

```
你的任务: 呈现影响面，让用户决策修复范围。

呈现内容:
  1. 修正内容确认（复述）
  2. 预计影响文件数 + 分层清单
  3. 是否有 BLOCKER（宪法冲突）
  4. 修复方案选项:
     A. 全量修复（推荐）— 修复所有受影响文件
     B. 核心修复 — 只修 L0+L1，L2+L3 标记为待处理
     C. 分批修复 — 先修 L0+L1，下次再修 L2+L3

等待用户确认后再动手。
```

### 阶段D: 逐层修复

```
你的任务: 从 L0 到 L3，逐层修复。每层验证通过才进下一层。

L0 底层修复顺序:
  1. 宪法文档（如果涉及公理）
  2. 概念注册表 S10（canonical定义 + 废弃别名）
  3. 术语注册表 S12（新废弃术语）
  4. 物理常量（如果涉及）
  → check.py --mode score → 验证

L1 协议层修复顺序:
  1. 角色档案（allowed_methods/forbidden_methods/动机/行为锚点）
  2. 势力版图（如果涉及）
  3. 科技树（节点定义/依赖关系）
  4. 人物关系图
  → check.py --mode score → 验证

L2 表示层修复顺序:
  1. 全卷骨架（如果影响卷结构）
  2. 剧情/伏笔追踪
  3. 叙事扩散/失忆线/奇遇线
  4. 章节索引
  → check.py --mode score → 验证

L3 会话层修复:
  1. 章节正文/场景
  2. 角色对话/描写
  → check.py --mode score → 验证

每层规则:
  - 一次修改 ≤5 个文件
  - 改完一层 → 运行 check.py → 确认 CLEAN
  - 通过才进下一层
```

### 阶段E: 验证与状态同步

```
1. check.py --mode score --min-score 0.8 → 全项目扫描
2. 确认: 零废弃术语残留 / 零宪法违规
3. 更新 S00_项目工作台.md:
   ### YYYY-MM-DD 修改日志
   - 用户修正: {简述}
   - 改动: {内容}
   - 影响面: {文件数}个文件, {L0}→{L1}→{L2}→{L3}
   - 验证: check.py → 得分 XX/100
4. 更新 S01_会话上下文.md（如果是重大变更: 新增角色/修改公理/调整主线）
5. 归档相关临时文档 → 创作正文/状态/归档/
6. 向用户汇报:
   - 改了什么（文件清单）
   - 影响面（多少文件受影响）
   - 验证结果（得分/残留/违规）
   - 是否有未完成的（如果选分批修复）
```

## 常见场景速查

### 场景1: 修正角色行为

```
用户: "严峰不会调监控。他是修真者。"

→ 阶段A: 严峰追踪手段从"监控/数据库"改为"神识(仅剩三尺)+灵场残余追踪"
→ 阶段B: L0(宪法第八章)+L1(严峰档案+注册表+术语表)+L2(骨架)+L3(~10章)
→ 阶段D:
  L0: 宪法第八章 allowed_methods/forbidden_methods
  L1: 严峰.md + S10(canonical+废弃别名) + S12(术语残留)
  L2: 全卷骨架_卷一.md 严峰相关行
  L3: 严峰出场的章节索引
→ 阶段E: check.py → CLEAN → 更新S00
```

### 场景2: 新增中间角色

```
用户: "只能是新增一个中间角色。林岳战力3500，主角不可能跑。"

→ 阶段A: 新增孟炽(炼精化气中期，Z=75，林岳的执行者)
→ 阶段B: L0(新概念注册)+L1(角色档案+人物关系)+L2(骨架+伏笔)+L3(ch82-83)
→ 阶段D:
  L0: S10_概念注册表 新增孟炽 + provenance: worldbuilding
  L1: 人物/卷一/孟炽.md + 人物关系图更新
  L2: 全卷骨架 ch82-83 追逃逻辑重写 + 伏笔追踪
  L3: ch82.md + ch83.md 场景重写
→ 阶段E: check.py → CLEAN → 更新S00+S01(重大变更)
```

### 场景3: 调整科技树时间线

```
用户: "潜蛟套件出现太晚。结合主角的风险意识，他肯定提前构思。"

→ 阶段A: 潜蛟从ch68"突然出现"改为ch32概念→ch76 I型的全卷生长
→ 阶段B: L1(科技树节点定义)+L2(骨架8章)+L3(8个章节索引)
→ 阶段D:
  L1: 赛博修真科技树.md A2节点 + 版本迭代表
  L2: 全卷骨架 相关8章的事件描述
  L3: ch32,39,48,63,68,76,82,83 章节索引中的潜蛟引用
→ 阶段E: check.py → 确认科技树→章节映射 8/8 命中
```

### 场景4: 用户说"先同步这个信息"

```
用户: "先同步这个信息"（给了一段新设定描述，没有具体修改指令）

→ 阶段A: 复述新信息，确认理解。主动询问:
  "这个信息是新增设定还是修正现有设定？"
  "是否有需要覆盖的旧版本？"
  如果用户没有明确→ 不要假设是覆盖。标记为新设定。
→ 阶段B: 按新设定计算影响面
→ 阶段C: 呈现影响面 + 询问修复范围
  如果用户说"只是同步，你先记着"→ 
    写入 S01_会话上下文.md "待确认设定"区
    不执行L2/L3修复
    下次会话开始时提醒用户确认
```

## 禁止的响应

```
❌ "好的，我记住了。"
   → 必须写入文件。记忆不可靠。

❌ "已修改。"（无影响面说明）
   → 必须列出改了哪些文件、为什么。

❌ 只改用户提到的一个文件
   → 必须计算涟漪。角色改→注册表+术语+骨架+章节全都要同步。

❌ 跳过阶段C直接动手
   → 任何影响面>5个文件的修改，必须先让用户确认修复范围。

❌ 改完不验证
   → 必须有 check.py 的输出。没验证=没完成。
```
