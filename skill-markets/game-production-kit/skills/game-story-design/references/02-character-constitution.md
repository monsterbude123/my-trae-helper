# 角色宪法与伏笔系统

## 角色宪法原则

> **角色宪法是唯一信息源** — 每个角色只有一份宪法（7 维定义），所有资产（立绘/音色/弧线/关系链）派生自宪法，不独立设计。

### 7 维宪法结构

| 维度 | 内容 | 派生资产 |
|------|------|----------|
| Want | 有意识的欲望（驱动行动的目标） | → 角色弧线、剧情冲突 |
| Fear | 不自知的恐惧（制造张力的核心） | → 恐怖陷阱、心理挣扎 |
| 年龄 | 精确年龄/年龄段 | → 音色设计（TTS）、立绘年龄感 |
| 性格 | 3-5 个关键词 | → 对话语气、选择倾向 |
| 外形 | 发型/服装/体型/特殊外观 | → 立绘提示词、模型选择 |
| 创伤 | 过去的伤害性经历 | → 伏笔背景、角色动机 |
| 弧光 | 全剧的变化轨迹 | → 结局走向、情感落点 |

### 铁律

- 角色音色从宪法推导，不可独立设计 instruct
- 角色立绘从宪法推导，不可脱离角色特征写提示词
- 角色关系链从宪法关系网推导，不可凭空添加剧情关系
- 宪法必须在策划阶段完成，素材生成前核对

每个主要角色填写 Want 和 Fear，人物弧光由 Want 与 Fear 之间的拉力驱动：

## 伏笔系统

### 4 阶段生命周期

每个伏笔经历 4 个阶段，不可跳跃：

| 阶段 | 描述 | 检查项 |
|------|------|--------|
| 埋点 | 首次出现，通常不易察觉 | 是否足够隐晦？ |
| 强化 | 再次提及，加深印象 | 是否在读者将要遗忘前出现？ |
| 揭示 | 真相浮出水面的一部分 | 是否出人意料又情理之中？ |
| 回收 | 结局中解决问题 | 是否解释了遗留疑问？ |

### 原则

- 关键伏笔应跨结局覆盖
- 真结局必须 100% 回收所有关键伏笔
- 失败类结局可故意保留悬念（设计意图，非遗漏）
- 每伏笔附带涟漪列表（"改 X → 影响 Y"），确保可检测可定位

### 伏笔矩阵模板

```markdown
| 伏笔元素 | 第一幕种植 | 第二幕发展 | 第三幕收割 |
|----------|-----------|-----------|-----------|
| | （何时、如何引入） | （如何加深/回响） | （如何揭露/解决） |
```

每个伏笔必须填满 3 列（种植→发展→收割）。

## 变量系统设计

变量数量 ≤ 8 个。类型：`string` / `number` / `boolean`。

```markdown
| 变量名 | 类型 | 初始值 | 含义 | 修改时机 |
|--------|------|--------|------|----------|
| clueCount | number | 0 | 已收集线索数 | 每次调查成功 |
| hasClue_xxx | boolean | false | 特定线索 | 对应调查点 |
```
