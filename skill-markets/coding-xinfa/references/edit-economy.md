# Edit Economy 编辑经济性细则

> 来源: coding-xinfa/SKILL.md §5
> 核心：同一文件的所有改动必须合并为 1~2 次 Edit 完成，禁止碎片化编辑。

---

## §1 决策树

```
准备修改文件
  │
  ├── 已规划好所有改动点？
  │     ├── 是 → 1 次 Edit 完成所有变更
  │     └── 否 → 🛑 停下，先列改动清单再动手
  │
  ├── 文件未读过？
  │     └── Read 1 次 → 形成清单 → 1~2 次 Edit 完成
  │
  ├── 改动点分散在多段？
  │     ├── < 3 段 → 1 次 Edit（用更大 old_string 上下文）
  │     └── ≥ 3 段 → 2~3 次 Edit（每段 1 次），不超过 3 次
  │
  └── 边写边发现遗漏？
        └── 🛑 立即停止，补全清单后一次性补完（不迭代补丁）
```

---

## §2 异常处理

| 异常场景 | 判定标准 | 处理动作 |
|---------|---------|---------|
| 文件超大单次 Edit 失败 | old_string 上下文过长无法定位唯一 | 按章节分 2~3 段，每段 1 次 Edit |
| 写完审计发现遗漏 | 改动后 Read 发现还有未改点 | 追加 1 次 Edit（不重写已成功部分） |
| 用户中途追加需求 | 用户新指令打断当前编辑 | 重新规划改动清单后再 Edit |
| 改完发现方向错误 | 改动逻辑根本性错误 | 撤回，Read 文件，重新规划 |

---

## §3 MUST

- MUST: 修改文件前先列出完整改动清单（哪怕内脑规划）
- MUST: 同一文件的所有改动合并为 1~2 次 Edit（特殊情况最多 3 次）
- MUST: 大文件先 Read 1 次再动手，避免边读边改
- MUST: 每次 Edit 后抽查 1 处确认改动正确

---

## §4 NEVER

- NEVER: 对同一文件做 ≥ 4 次碎片化 Edit
- NEVER: 边改边想、发现漏了再补的迭代补丁模式
- NEVER: 不读文件就连续 Edit
- NEVER: 一次 Edit 改动 > 200 行（过大易出错，应分段）
